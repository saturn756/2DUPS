# 04 接口规范

本文件定义项目内部跨模块接口。接口采用可序列化的 JSON 结构表达；图像、掩码、点集和历史轨迹等大对象使用引用，不直接嵌入消息。数据流和连接编号见 [`../dataflow/03_数据流与连接逻辑.md`](../dataflow/03_数据流与连接逻辑.md)。

## 4.1 接口清单

| 接口 | 名称 | 生产者 → 消费者 | 粒度 |
|---|---|---|---|
| I1 | `DatasetManifest` | M1 → 全链路/评测 | 运行级 |
| I2 | `CalibratedFrame` | M1 → M2，标定状态供 M6 读取 | 帧级 |
| I3 | `ImageVariantSet`、`QualityReport` | M2 → M3/M4/M5，质量报告供评测 | 帧级 |
| I4 | `MatchResult` | M3 → M4 跟踪/M6 | 相邻图像对级 |
| I5 | `DetectionSet` | M4 检测 → M4 跟踪/评测 | 帧级 |
| I6 | `TrackSet` | M4 跟踪 → M6 | 帧级 |
| I7 | `SegmentationMap` | M5 → M6 | 帧级 |
| I8 | `SceneGraph2D` | M6 → 对外输出 | 帧级或明确窗口 |
| I9 | `EvaluationRecord` | 评测 → 归档/报告 | 运行级 |

## 4.2 通用格式和约束

### 必需元数据

所有跨模块对象必须包含：

```json
{
  "interface": "Ix",
  "schema_version": "1.0",
  "producer_ref": "module.implementation",
  "config_ref": "configs/module.yaml"
}
```

逐帧对象还必须包含 `sequence_id`、`frame_id`；图像相关对象还必须包含 `variant_id`、`coordinate_space`。图像对对象使用 `pair.frame_a`、`pair.frame_b`。

### 引用格式

大对象统一用如下可序列化引用：

```json
{
  "uri": "outputs/segmentation/seq_001/000001.png",
  "kind": "class_map",
  "checksum": "sha256:..."
}
```

`checksum` 可以在开发早期省略具体值，但字段不能改成不可追溯的本地内存地址。

### 状态原则

- 空集合不等于失败：例如没有目标时 `objects=[]`，同时 `status="ok"`；检测失败则 `status="failed"` 或 `detection_missing=true`。
- 可选输入缺失必须显式记录；不能用其它帧、其它序列或其它图像版本替代。
- 类别必须引用 `class_schema_ref`；下游不能仅凭 `class_id` 猜语义。
- 允许新增未知字段；改变字段语义、删除字段或改变关系含义时必须升大版本。
- 不输出单目 RGB 无法可靠支持的三维距离、真实速度、前后深度关系、TTC 或风险结论。

## 4.3 I1 `DatasetManifest`

### 字段

| 字段 | 要求 |
|---|---|
| `manifest_id`、`version` | 清单身份和版本 |
| `source`、`license` | 数据集来源和许可 |
| `splits` | 训练/验证/测试到序列的映射 |
| `samples[]` | 样本 ID、序列 ID、媒体引用、可选标注引用、切片标签 |
| `checksum` | 清单内容校验 |

### JSON 示例

```json
{
  "interface": "I1",
  "schema_version": "1.0",
  "manifest_id": "bdd100k-demo",
  "version": "2026-09-23",
  "source": "BDD100K",
  "license": "dataset-license",
  "splits": {
    "test": ["seq_001"]
  },
  "samples": [
    {
      "sample_id": "seq_001",
      "sequence_id": "seq_001",
      "media_ref": {
        "uri": "data/raw/seq_001.mp4",
        "kind": "video",
        "checksum": "sha256:video..."
      },
      "annotation_ref": null,
      "slice_tags": ["normal"]
    }
  ],
  "checksum": "sha256:manifest...",
  "producer_ref": "m1.dataset_manifest",
  "config_ref": "configs/common.yaml"
}
```

缺少 I1 时不启动运行；模块不能从文件名自行推断数据集、切分或许可。

## 4.4 I2 `CalibratedFrame`

### 语义

表示 M1 接受的一帧图像及其标定状态。`calibration.status` 只说明参数是否可用和适用，不代表系统已经获得深度或三维位置。

### JSON 示例：标定缺失也合法

```json
{
  "interface": "I2",
  "schema_version": "1.0",
  "sequence_id": "seq_001",
  "frame_id": "seq_001:000001",
  "timestamp": 0.033,
  "camera_id": "camera_front",
  "media_ref": {
    "uri": "data/frames/seq_001/000001.jpg",
    "kind": "image",
    "checksum": "sha256:frame..."
  },
  "image_size": {
    "width": 1280,
    "height": 720
  },
  "coordinate_space": "pixel",
  "calibration": {
    "status": "missing",
    "calibration_ref": null,
    "reason": "dataset_does_not_provide_verified_calibration"
  },
  "manifest_ref": "bdd100k-demo",
  "producer_ref": "m1.input_loader",
  "config_ref": "configs/m1_calibration.yaml"
}
```

允许的标定状态为 `valid`、`missing`、`stale`。`missing/stale` 时，M2 不得伪造校正版本，M6 只能使用图像平面语义。

## 4.5 I3 `ImageVariantSet` 与 `QualityReport`

### 结构约束

- `raw` 永远存在；
- `rectified` 只有在标定有效且适用时才能存在；
- `enhanced` 可选，必须记录父版本和处理参数；
- `default_variant` 必须等于 `variants[].variant_id` 中的一项；
- M3、M4、M5 对同一帧必须消费相同的 `default_variant`。

### `ImageVariantSet` JSON 示例

```json
{
  "interface": "I3",
  "schema_version": "1.0",
  "kind": "ImageVariantSet",
  "sequence_id": "seq_001",
  "frame_id": "seq_001:000001",
  "default_variant": "raw",
  "variants": [
    {
      "variant_id": "raw",
      "kind": "raw",
      "media_ref": {
        "uri": "data/frames/seq_001/000001.jpg",
        "kind": "image",
        "checksum": "sha256:frame..."
      },
      "parent_variant_id": null,
      "coordinate_space": "pixel",
      "params_ref": null
    },
    {
      "variant_id": "enhanced",
      "kind": "enhanced",
      "media_ref": {
        "uri": "outputs/m2/seq_001/000001_enhanced.jpg",
        "kind": "image",
        "checksum": "sha256:enhanced..."
      },
      "parent_variant_id": "raw",
      "coordinate_space": "pixel",
      "params_ref": "outputs/m2/seq_001/000001_params.json"
    }
  ],
  "calibration_status": "missing",
  "producer_ref": "m2.preprocess",
  "config_ref": "configs/m2_preprocess.yaml"
}
```

### `QualityReport` JSON 示例

```json
{
  "interface": "I3",
  "schema_version": "1.0",
  "kind": "QualityReport",
  "sequence_id": "seq_001",
  "frame_id": "seq_001:000001",
  "metrics": {
    "brightness_mean": 92.4,
    "blur_laplacian_variance": 118.7,
    "overexposed_fraction": 0.01
  },
  "operations": [
    {
      "operation": "rectification",
      "status": "skipped",
      "input_variant_id": "raw",
      "output_variant_id": null,
      "reason": "calibration_missing"
    },
    {
      "operation": "enhancement",
      "status": "generated",
      "input_variant_id": "raw",
      "output_variant_id": "enhanced",
      "params_ref": "outputs/m2/seq_001/000001_params.json"
    }
  ],
  "gate_decision": "use_raw",
  "selected_variant_id": "raw",
  "reason": ["enhanced_version_not_better_on_validation_slice"],
  "producer_ref": "m2.quality_gate",
  "config_ref": "configs/m2_preprocess.yaml"
}
```

## 4.6 I4 `MatchResult`

第一版 `transform.semantics` 必须是 `image_plane_transform`。它可用于图像平面上的跟踪补偿，不能被解释为真实自运动、深度或米制位移。

```json
{
  "interface": "I4",
  "schema_version": "1.0",
  "sequence_id": "seq_001",
  "pair": {
    "frame_a": "seq_001:000001",
    "frame_b": "seq_001:000002",
    "variant_id": "raw",
    "coordinate_space": "pixel"
  },
  "status": "ok",
  "transform": {
    "type": "homography",
    "semantics": "image_plane_transform",
    "matrix": [
      [1.002, 0.004, 2.1],
      [0.001, 1.001, 0.7],
      [0.00001, 0.00001, 1.0]
    ],
    "inlier_ratio": 0.74,
    "residual": 1.8
  },
  "keypoints_ref": {
    "uri": "outputs/m3/seq_001/000001_000002_keypoints.npz",
    "kind": "keypoints",
    "checksum": "sha256:keypoints..."
  },
  "matches_ref": {
    "uri": "outputs/m3/seq_001/000001_000002_matches.json",
    "kind": "matches",
    "checksum": "sha256:matches..."
  },
  "producer_ref": "m3.sift_flann_ransac",
  "config_ref": "configs/m3_geometry.yaml"
}
```

`status` 为 `unreliable` 或 `failed` 时，`transform` 不得作为有效证据；消费方必须记录没有使用它。

## 4.7 I5 `DetectionSet`

```json
{
  "interface": "I5",
  "schema_version": "1.0",
  "sequence_id": "seq_001",
  "frame_id": "seq_001:000002",
  "variant_id": "raw",
  "coordinate_space": "pixel",
  "image_size": {
    "width": 1280,
    "height": 720
  },
  "status": "ok",
  "detection_missing": false,
  "class_schema_ref": "schemas/bdd100k_classes_v1.json",
  "objects": [
    {
      "detection_id": "det_0001",
      "class_ref": "vehicle.car",
      "bbox": {
        "x1": 500,
        "y1": 300,
        "x2": 700,
        "y2": 500
      },
      "score": 0.91
    }
  ],
  "producer_ref": "m4.yolo_detector",
  "config_ref": "configs/m4_detection_tracking.yaml"
}
```

若当前帧确实没有目标，仍输出 `status="ok"`、`objects=[]`、`detection_missing=false`；若检测过程失败，则改为失败状态并说明原因。

```json
{
  "interface": "I6",
  "schema_version": "1.0",
  "sequence_id": "seq_001",
  "frame_id": "seq_001:000002",
  "variant_id": "raw",
  "coordinate_space": "pixel",
  "status": "ok",
  "detection_missing": false,
  "tracks": [
    {
      "track_id": "track_001",
      "class_ref": "vehicle.car",
      "current_bbox": {
        "x1": 502,
        "y1": 301,
        "x2": 701,
        "y2": 501
      },
      "state": "tracked",
      "confidence": 0.89,
      "age": 12,
      "missed_frames": 0,
      "last_detection_id": "det_0001",
      "history_ref": {
        "uri": "outputs/tracks/track_001.jsonl",
        "kind": "track_history",
        "checksum": "sha256:history..."
      }
    }
  ],
  "association": {
    "method": "bytetrack",
    "motion_compensation_used": false,
    "match_result_ref": null,
    "reason": "match_missing"
  },
  "producer_ref": "m4.bytetrack",
```

```json
{
  "interface": "I7",
  "schema_version": "1.0",
  "sequence_id": "seq_001",
  "frame_id": "seq_001:000002",
  "variant_id": "raw",
  "coordinate_space": "pixel",
  "source_size": {
    "width": 1280,
    "height": 720
  },
  "map_size": {
    "width": 1280,
    "height": 720
  },
  "class_map_ref": {
    "uri": "outputs/m5/seq_001/000002.png",
    "kind": "class_map",
    "checksum": "sha256:classmap..."
  },
  "class_schema_ref": "schemas/cityscapes_road_subset_v1.json",
  "alignment_ref": {
    "uri": "outputs/m5/seq_001/000002_alignment.json",
    "kind": "source_alignment",
    "checksum": "sha256:alignment..."
  },
  "status": "ok",
  "producer_ref": "m5.pidnet_s",
  "config_ref": "configs/m5_segmentation.yaml"

```

若模型内部输出尺寸不同，`map_size` 与 `alignment_ref` 必须真实反映映射；不能只写源图尺寸而省略缩放或裁剪信息。

## 4.10 I8 `SceneGraph2D`

### 关系语义

基础关系集合为 `belongs_to`、`inside_region`、`left_of`、`right_of`、`overlaps`、`appears_in`。它们均是当前图像坐标或明确窗口中的 2D 关系。

`geometry_status` 只允许：

- `image_plane`：输入正常，但语义限于图像平面；
- `degraded`：输入缺失、未对齐或几何证据不可靠，结果进一步收窄。

基础版没有 `full`，因为没有深度和地面模型时不能声称完整空间几何。

### JSON 示例

```json
{
  "interface": "I8",
  "schema_version": "1.0",
  "sequence_id": "seq_001",
  "frame_id": "seq_001:000002",
  "variant_id": "raw",
  "coordinate_space": "pixel",
  "window": {
    "frame_ids": ["seq_001:000002"],
    "uses_future_frames": false
  },
  "geometry_status": "image_plane",
  "nodes": [
    {
      "node_id": "track_001",
      "type": "track",
      "ref": "track_001",
      "class_ref": "vehicle.car"
    },
    {
      "node_id": "region_road",
      "type": "region",
      "ref": "class:road",
      "class_ref": "region.road"
    }
  ],
  "edges": [
    {
      "src": "track_001",
      "dst": "region_road",
      "relation": "belongs_to",
      "evidence": [
        {
          "type": "bbox_bottom_center_in_mask",
          "source": "I6+I7",
          "details": {
            "sample_count": 5,
            "road_fraction": 0.8
          }
        }
      ],
      "confidence": 0.84
    }
  ],
  "missing_inputs": [],
  "provenance": {
    "track_set": "m4.bytetrack",
    "segmentation_map": "m5.pidnet_s",
    "geometry": null
  },
  "producer_ref": "m6.rule_based_scene_graph",
  "config_ref": "configs/m6_topology.yaml"
}
```

M6 不输出 `front_behind`、`conflict`、真实距离、速度或风险边。缺少分割时可以保留有证据的 `left_of`/`right_of` 等目标侧关系，但必须在 `missing_inputs` 中写明原因。

## 4.11 I9 `EvaluationRecord`

```json
{
  "interface": "I9",
  "schema_version": "1.0",
  "run_id": "run_20260923_001",
  "module_ref": "M6",
  "sub_block": "scene_graph_2d",
  "sequence_id": "seq_001",
  "slice": {
    "name": "normal",
    "tags": ["daylight", "urban"]
  },
  "metrics": {
    "alignment_success_rate": 0.98,
    "region_membership_accuracy": 0.91,
    "left_right_accuracy": 0.88,
    "graph_validity_rate": 1.0,
    "degradation_accuracy": 0.95
  },
  "failures": [
    {
      "sample_ref": "seq_001:000137",
      "failure_tag": "segmentation_unaligned",
      "cause_module": "M5"
    }
  ],
  "implementation_ref": "m6.rule_based_scene_graph",
  "manifest_ref": "bdd100k-demo",
  "evaluation_config_ref": "configs/common.yaml",
  "producer_ref": "evaluation.runner",
  "config_ref": "configs/m6_topology.yaml"
}
```

`evaluation_config_ref` 用于记录评测运行自身的配置，`config_ref` 记录被评测模块的配置；两者都必须可追溯。

## 4.12 对齐与降级规则

| 规则 | 要求 |
|---|---|
| R1 帧对齐 | `sequence_id`、`frame_id` 必须一致 |
| R2 版本对齐 | M4/M5/M6 的 `variant_id` 必须一致 |
| R3 坐标对齐 | `coordinate_space` 必须一致；M5 必须有源帧映射 |
| R4 来源追溯 | 每个对象带 `producer_ref`、`config_ref` 或其等价来源引用 |
| R5 失败显式 | 使用 `status`、`state`、`missing_inputs`，不以空值掩盖 |
| R6 证据充分 | 每条 `SceneGraph2D.edges[]` 都有证据类型和来源 |
| R7 不用未来帧 | `window.uses_future_frames=false`；消费时机与 pair 约束一致 |

降级时的最小行为：标定缺失仍可运行但只输出图像平面关系；M3 失败不阻塞 M4/M5；M4 或 M5 缺失不伪造数据；M6 不因证据不足补边。

## 4.13 版本和变更流程

1. 新增可选字段：升小版本，消费方必须忽略未知字段。
2. 删除字段、改变字段语义或改变关系集合：升大版本，并同步数据流、模块规范和配置。
3. 新增或删除连接边：先改 `03_数据流与连接逻辑.md`，再改本文件。
4. 模块职责变更：先改 `01_系统架构.md` 和 `02_模块规范.md`，再检查本文件和配置。
5. 每次变更都要保留一个有效 JSON 示例，并通过解析检查。
