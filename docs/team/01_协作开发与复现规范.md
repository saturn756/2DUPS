# 2DUPS 多服务器协作与复现规范（v1）

本规范面向各自使用 Linux 服务器的成员。目标是让同一代码提交、同一数据和同一参数产生可比较的结果；**不要求服务器上的绝对路径相同**。以下路径除 Conda 环境外，均相对仓库根目录。当前可运行的基线是 BDD100K 五段视频的 DataLoader 与 M2；M3–M6 的权重、训练和完整链路尚未实现，相关目录是团队约定，不代表文件已存在。

## 1. 一页约定

| 内容 | 仓库内位置 | 是否进 Git | 说明 |
|---|---|---|---|
| 代码、接口和共享超参数 | `src/`、`configs/` | 是 | 每次对照实验记录 Git commit 和配置内容哈希 |
| 环境规格 | `environment.yml`、`requirements-lock-linux-py311.txt` | 是 | Linux x86_64 / Python 3.11 基线；其他平台另立锁文件 |
| 数据集定义和切分 | `configs/dataset_manifest.yaml` | 是 | 只放相对路径、来源、许可、split 和样本信息 |
| 五段样本校验和 | `configs/datasets/bdd100k-five.sha256` | 是 | SHA-256 匹配后才视为同一份数据 |
| 原始数据 | `data/raw/bdd100k/` | 否 | 每台服务器自行合法获取，不改名或覆盖 |
| 中间数据 | `data/interim/`、`data/processed/` | 否 | 必须标明生成脚本、输入清单和参数 |
| 模型权重 | `checkpoints/<模块>/<模型>/<版本>/` | 否 | 元数据、来源和 SHA-256 必须随权重保存 |
| 运行日志和输出 | `logs/`、`outputs/`、`runs/` | 否 | 保存运行记录、指标、失败样本及生成图像 |

不要在共享配置或代码中写 `/home/某用户/...`，也不要依赖另一项目的 Conda 环境。个人服务器路径、账号、代理、镜像、密钥和 token 不入库。`.gitignore` 只能防止常规误加，提交前仍要检查 `git diff --cached --name-only`。

## 2. 环境：先复现基线，再增依赖

当前基线在 Linux x86_64、Python 3.11.16 上验证。每人使用自己账号下的项目专用 Conda 环境，不共享 `demo` 等其他项目环境。`environment.yml` 固定 Python；`requirements-lock-linux-py311.txt` 固定当前 Python 包版本。这个锁文件**没有 wheel 哈希，也不锁定 GPU 驱动、CUDA 或系统库**，因此是“已验证版本集”，不是跨机器字节级完全一致的容器镜像。

```bash
cd /path/to/2DUPS
conda env create -f environment.yml
conda activate 2dups
python -m pip install -r requirements-lock-linux-py311.txt
python -m pip install --no-deps -e .
python -m pip check
python -m pytest -q
python -c 'import sys, av, cv2, numpy; print(sys.version, av.__version__, cv2.__version__, numpy.__version__)'
```

服务器若未把 Conda 加入 shell，可先 `source <conda安装目录>/etc/profile.d/conda.sh`。`zsf` 服务器上的现有环境是 `/home/zsf/.conda/envs/2dups`，可直接用该环境的 `bin/python`；这只是该服务器的路径，不是共享接口。`requirements.txt` / `requirements-dev.txt` 用于日常开放式开发，不可替代锁文件做可比实验。

新增依赖时，在 `requirements.txt` 说明归属模块，验证后更新对应平台锁文件，并在 PR 写明版本变化。将来 M4/M5 用 PyTorch、CUDA 或模型框架时，要另列 GPU/CUDA/驱动兼容矩阵和安装锁文件；当前仓库**没有**可复现的 GPU 训练环境，不能拿现有 M2 环境直接宣称复现模型结果。

## 3. 数据：来源、精确文件和任务能力

目前仅固定 `configs/dataset_manifest.yaml` 中的 5 段 BDD100K 训练视频及同名 JSON。官方来源、下载命令、大小和格式见 [五段小样本文档](../datasets/08_BDD100K_五段小样本.md)。在仓库根目录运行该文档的两条 `python scripts/download_bdd100k_subset.py ...` 命令；脚本只按 ZIP 成员名抽取所需文件，默认写到 `data/raw/bdd100k/`。若官方源不可达，可通过团队认可且符合数据许可的渠道传递这 **10 个原文件**，目标路径和校验和必须保持一致；不要把视频/标注上传 GitHub。

下载或复制完成后，执行：

```bash
cd /path/to/2DUPS
sha256sum -c configs/datasets/bdd100k-five.sha256
python scripts/run_dataloader.py --max-frames 1
```

校验必须显示 **10/10 OK**。`sha256sum` 是 Linux 命令；macOS 可用 `shasum -a 256 -c`。任何文件缺失或哈希不一致都应先定位来源，不能直接改 checksum 文件使检查通过。新数据集或新切分应另增 manifest、来源/许可说明和文件校验清单，并在 PR 中写清与旧结果是否可比；不要在原 manifest 下偷偷增加样本或改变 split。

这 5 个 JSON 每段只有约第 10 秒的一帧标注，主要用于接入和检测标签烟雾测试；`objects[].id` 不是跨帧跟踪 ID，不能拿它评估 IDF1，也没有逐帧分割真值。五段都在 `train` split，**不能作为正式泛化测试集**。任何正式 M4/M5 指标必须另写数据/切分规范。

## 4. Checkpoint：统一位置与来源证明

统一目录示例（模型名/版本用小写英文、数字、连字符或下划线）：

```text
checkpoints/
└── m4_detection_tracking/
    └── detector-name/
        └── v1/
            ├── weights/
            │   └── best.pt
            └── metadata.yaml
```

`checkpoints/` 整体被 Git 忽略；**权重文件和随权重本地保存的 metadata.yaml 都不入 Git**。团队共享的是 checkpoint 的获取说明/登记记录（可在 PR、项目文档或获批的制品目录登记），不是某个人服务器上的绝对路径。尚未选定共享制品服务时，不要在文档里写一个不存在的下载 URL。任何模块要使用权重，配置中只写仓库相对路径，例如 `checkpoints/m4_detection_tracking/detector-name/v1/weights/best.pt`，并在启动时检查文件存在及 SHA-256 匹配；不得静默从网络下载“最新版”或默认回退到其他权重。

每个权重目录必须有 `metadata.yaml`，至少记录：

```yaml
artifact_id: m4-detector-name-v1
file: weights/best.pt
sha256: "<64位十六进制SHA-256>"
source_type: pretrained             # 或 trained_in_project
source_url_or_transfer_record: "<官方下载/发布页或团队传递记录>"
license: "<权重许可及使用条件>"
model_name: detector-name
model_version: v1
framework_version: "<实际版本>"
task: detection
class_schema_ref: "<类别映射文件或版本>"
input_spec: "<RGB/BGR、尺寸、归一化、letterbox 等>"
code_commit: "<训练/导出时的完整 Git SHA；外部权重填上游版本>"
config_ref: "<训练/导出配置路径或外部说明>"
dataset_manifest_ref: "<训练数据清单 ID/版本；外部未知则明确写 unknown>"
seed: "<训练种子；外部未知则明确写 unknown>"
```

复制后可用 `sha256sum checkpoints/.../weights/best.pt` 对照 metadata。外部预训练权重若缺类别映射、输入规范或许可，不直接接入共享基线；先补齐记录并由负责模块的成员核对。自己训练的权重应同时保留训练日志、epoch、优化器/学习率、数据切分、验证指标和选择 `best.pt` 的依据。

## 5. 参数、运行记录和可比性

共享默认参数放 `configs/common.yaml` 和各 `configs/m*_*.yaml`；数据集身份/切分只在 manifest 定义。当前 M2 的质量门控阈值和处理参数已写在 `configs/m2_preprocess.yaml`，仍是小样本初值，**没有下游收益证明**。个人实验不要直接改共享默认值而不记录：复制完整模块配置到 `configs/experiments/<模块>/<实验名>.yaml` 后用支持 `--config` 的入口运行，例如 M2 的 `python scripts/run_m2.py --config configs/experiments/m2/lowlight-a.yaml ...`。当前配置加载是浅层合并，实验文件必须是完整模块配置，不是只写几个覆盖字段。确定采纳后再通过 PR 修改共享默认配置。

每次报告实验结果，至少在 `runs/<run_id>/run.yaml` 或相应报告里记录以下字段；`runs/` 不入 Git，团队交流结果时提交脱敏摘要/表格，不发原始数据：

```yaml
run_id: "2026-09-26T120000Z_m2_example"
git_commit: "<完整40位Git SHA>"
working_tree_clean: true
environment: {platform: linux-64, python: "3.11.16", lock_file: requirements-lock-linux-py311.txt}
dataset: {manifest: configs/dataset_manifest.yaml, manifest_checksum: "<I1 checksum>", file_checksums: configs/datasets/bdd100k-five.sha256, split: train}
module: M2
implementation: clahe_lab
config_ref: configs/m2_preprocess.yaml
config_sha256: "<实际配置文件SHA-256>"
checkpoint_artifact_id: null      # 无模型的 M2 填 null；模型运行必须填写
checkpoint_sha256: null
seed: null                        # 随机实验必须填写整数
command: "python scripts/run_m2.py --max-frames 320 --stride 100"
metrics_ref: "<运行结果路径或报告链接>"
notes: "smoke test only; not a held-out evaluation"
```

比较两次结果前核对：数据清单/文件哈希、split、代码提交、环境锁文件、配置哈希、权重哈希、随机种子和指标口径。任意一项不同就标注差异，不能简单宣称某算法更好。可比较的模型实验还需固定图像预处理、类别映射、评测脚本及版本。M2 的生成图像和质量报告写入 `outputs/m2/<配置哈希>/<序列>/`；这些是运行产物，不是 checkpoint。

## 6. 团队交付检查

1. 从共享分支取得明确的 Git 提交；不要把未提交改动当作团队基线。
2. 用独立环境和对应锁文件安装；运行 `python -m pip check`、`python -m pytest -q`。
3. 按 manifest 获取数据，并校验文件 SHA-256；运行一段 DataLoader 冒烟测试。
4. 若模块需要权重，核对 `metadata.yaml`、许可、输入规范和权重 SHA-256。
5. 用提交的配置运行；保存运行记录及失败原因。
6. PR 至少说明修改的接口、配置/依赖/数据/权重版本、复现命令和测试结果；不得提交原始数据、权重、密钥或 `outputs/`。
