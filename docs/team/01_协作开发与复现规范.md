# 2DUPS 多服务器协作与复现规范（v1）

本规范面向**各自在不同 Linux 服务器上**工作的成员。每人独立 clone 仓库、创建环境、取得数据和权重；不共享服务器、账号、Conda 安装或运行目录。当前只要求代码与配置、数据文件、使用到的 checkpoint 保持一致，不规定运行结果归档或正式指标比较。各服务器的仓库绝对位置可以不同；本文件列出的仓库内路径均相对各自的仓库根目录。当前可运行的基线是 BDD100K 五段视频的 DataLoader 与 M2；M4 的 YOLO11n 检测代码尚无权重、未验证真实推理；M3、M4 跟踪、M5–M6 和完整链路尚未实现。

## 1. 一页约定

| 内容 | 仓库内位置 | 是否进 Git | 说明 |
|---|---|---|---|
| 代码、接口和共享参数 | `src/`、`configs/` | 是 | 使用同一 Git 提交；配置随代码一起版本化 |
| 环境规格 | `environment.yml`、`requirements-lock-linux-py311.txt` | 是 | Linux x86_64 / Python 3.11 / PyTorch CUDA 12.8 基线；其他平台另立锁文件 |
| 数据集定义和切分 | `configs/dataset_manifest.yaml` | 是 | 只放相对路径、来源、许可、split 和样本信息 |
| 五段样本校验和 | `configs/datasets/bdd100k-five.sha256` | 是 | SHA-256 匹配后才视为同一份数据 |
| 原始数据 | `data/raw/bdd100k/` | 否 | 每台服务器自行合法获取，不改名或覆盖 |
| 中间数据 | `data/interim/`、`data/processed/` | 否 | 必须标明生成脚本、输入清单和参数 |
| 模型权重 | `checkpoints/<模块>/<模型>/<版本>/` | 否 | 用到模型时按共享配置中的 SHA-256 核对文件 |
| 本地输出 | `logs/`、`outputs/`、`runs/` | 否 | 工具生成的内容留在本机，不要求协作时归档 |

共享配置、代码和文档不得写入任何成员的绝对文件路径，也不能依赖其他成员或其他项目的 Conda 环境。个人服务器地址、账号、代理、镜像、密钥和 token 不入库。`.gitignore` 只能防止常规误加，提交前仍要检查 `git diff --cached --name-only`。

## 2. 环境：先复现基线，再增依赖

当前基线在 Linux x86_64、Python 3.11.16、NVIDIA 驱动 570.144 上验证。每人在自己的服务器创建名为 `2dups` 的项目专用 Conda 环境，不复用其他项目环境。`environment.yml` 固定 Python；`requirements-lock-linux-py311.txt` 固定当前 Python 包版本，包括 PyTorch 2.8.0 + CUDA 12.8、torchvision 0.23.0 + CUDA 12.8 与 Ultralytics 8.3.184。其他服务器需要兼容 CUDA 12.8 的 NVIDIA 驱动。锁文件**没有 wheel 哈希，也不锁定驱动或系统库**，因此不是跨机器字节级完全一致的容器镜像。

```bash
conda env create -f environment.yml
conda activate 2dups
python -m pip install -r requirements-lock-linux-py311.txt
python -m pip install --no-deps -e .
python -m pip check
python -m pytest -q
python -c 'import sys, av, cv2, numpy; print(sys.version, av.__version__, cv2.__version__, numpy.__version__)'
python -c 'import torch, torchvision, ultralytics; print(torch.__version__, torchvision.__version__, ultralytics.__version__, torch.version.cuda, torch.cuda.is_available())'
```

上述命令从各自 clone 的仓库根目录运行；首次 clone 和进入目录的命令见 [README](../../README.md)。若 `conda activate` 不可用，请按**本机** Conda 安装说明初始化当前 shell，然后重开 shell；不要复制其他成员的环境路径。已有 `2dups` 环境不需再次 `conda env create`，但要核对依赖锁文件。`requirements.txt` / `requirements-dev.txt` 用于日常开放式开发，不可替代锁文件做可比实验。

新增依赖时，在 `requirements.txt` 说明归属模块，验证后更新对应平台锁文件。M4 推理依赖已安装并验证 GPU 张量运算与 torchvision NMS，**但尚无 YOLO11n 权重，未验证真实检测推理或精度**。GPU 训练参数与结果复现仍不在当前基线范围内。

## 3. 数据：来源、精确文件和任务能力

目前仅固定 `configs/dataset_manifest.yaml` 中的 5 段 BDD100K 训练视频及同名 JSON。官方来源、下载命令、大小和格式见 [五段小样本文档](../datasets/08_BDD100K_五段小样本.md)。在仓库根目录运行该文档的两条 `python scripts/download_bdd100k_subset.py ...` 命令；脚本只按 ZIP 成员名抽取所需文件，默认写到 `data/raw/bdd100k/`。若官方源不可达，可通过团队认可且符合数据许可的渠道传递这 **10 个原文件**，目标路径和校验和必须保持一致；不要把视频/标注上传 GitHub。

下载或复制完成后，执行：

```bash
sha256sum -c configs/datasets/bdd100k-five.sha256
python scripts/run_dataloader.py --max-frames 1
```

校验必须显示 **10/10 OK**。`sha256sum` 是 Linux 命令；macOS 可用 `shasum -a 256 -c`。任何文件缺失或哈希不一致都应先定位来源，不能直接改 checksum 文件使检查通过。新数据集或新切分应另增 manifest、来源/许可说明和文件校验清单，并在 PR 中写清与旧结果是否可比；不要在原 manifest 下偷偷增加样本或改变 split。

这 5 个 JSON 每段只有约第 10 秒的一帧标注，主要用于接入和检测标签烟雾测试；`objects[].id` 不是跨帧跟踪 ID，不能拿它评估 IDF1，也没有逐帧分割真值。五段都在 `train` split，**不能作为正式泛化测试集**。任何正式 M4/M5 指标必须另写数据/切分规范。

## 4. Checkpoint：统一路径与文件哈希

统一目录示例（模型名/版本用小写英文、数字、连字符或下划线）：

```text
checkpoints/
└── m4_detection_tracking/
    └── detector-name/
        └── v1/
            └── best.pt
```

`checkpoints/` 整体被 Git 忽略。M4/M5 等模块真正接入权重时，在对应的 `configs/m*_*.yaml` 中提交**仓库相对路径和预期 SHA-256**；每位成员自行取得同一权重文件，用 `sha256sum <相对权重路径>` 核对，不匹配就不运行该模型。现阶段不要求另写 `metadata.yaml`、权重登记表或训练日志；M4 检测适配器尚未配置权重，M4 跟踪和 M5 尚未实现。

## 5. 参数与当前阶段的一致性

共享参数放 `configs/common.yaml` 和各模块配置，数据集与切分放 `configs/dataset_manifest.yaml`。配置随 Git 提交固定；个人试验可以在本机使用其他配置，但只有把选定配置提交后才算团队共同版本。当前 M2 阈值仍是小样本初值，没有下游收益证明。

当前协作只核对三件事：**同一 Git 提交（含代码与配置）、同一数据文件（按清单校验）、用到模型时同一 checkpoint（按 SHA-256 校验）**。环境按第 2 节安装。无需为每次运行创建 `run.yaml`、填写参数哈希或保存失败原因；M2 自动产生的质量报告和图片仅是本地输出，不要求团队共享。以后需要正式比较指标时，再单独制定评测记录规则。

## 6. 团队交付检查

1. 从共享分支取得明确的 Git 提交；不要把未提交改动当作团队基线。
2. 用独立环境和对应锁文件安装；运行 `python -m pip check`、`python -m pytest -q`。
3. 按 manifest 获取数据，并校验文件 SHA-256；运行一段 DataLoader 冒烟测试。
4. 若模块需要权重，核对共享配置中的相对路径和 SHA-256；不用模型时跳过。
5. 共享配置随代码提交，不要求保存逐次运行记录或失败原因。
6. 提交前确认测试通过，并检查没有把原始数据、权重、密钥或 `outputs/` 加入 Git。
