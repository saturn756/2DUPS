# M2 图像预处理与质量门控

## 1. 模块定位

M2 接收 M1 输出的 `CalibratedFrame`，对每帧图像完成输入规范化、质量评价、条件性预处理和版本选择。M2 的输出供 M3 帧间几何、M4 检测跟踪和 M5 语义分割共同使用。

M2 的核心原则是：原始图像始终保留，增强只在质量门控触发时执行，所有下游支路使用同一个 `default_variant`。

M2 不负责目标检测、跟踪、分割或驾驶风险判断。

## 2. 第一阶段范围

第一阶段只实现下列在线处理：

| 能力 | 第一阶段策略 | 说明 |
|---|---|---|
| 输入规范化 | 必须执行 | 统一 RGB、数据类型、图像尺寸元数据和坐标语义 |
| 质量评价 | 必须执行 | 计算亮度、曝光、对比度、模糊、噪声等指标 |
| 低照度增强 | 条件执行 | LAB 空间的 L 通道 CLAHE，必要时叠加轻度 Gamma |
| 轻度去噪 | 条件执行 | 只在噪声较高且未严重模糊时执行 |
| 去畸变 | 条件执行 | 只有标定有效且适用时生成 `rectified` |
| 去雨、去雾、去模糊、超分辨率 | 暂不进入主链路 | 后续通过独立对照实验评估 |

去雨、去雾和超分辨率可能改变目标边缘或生成伪影，第一阶段先通过训练数据增强提升模型对这些情况的鲁棒性。

## 3. 输入与输出

### 3.1 输入

输入接口为 I2 `CalibratedFrame`，至少包含：

- `sequence_id`、`frame_id` 和时间戳；
- 图像引用和图像尺寸；
- 当前坐标空间；
- 标定状态 `valid`、`missing` 或 `stale`。

当标定状态为 `missing` 或 `stale` 时，M2 不生成伪造的去畸变版本，但不阻塞 RGB 图像处理。

### 3.2 输出

输出接口为 I3：

- `ImageVariantSet`：保存 `raw`、可选的 `rectified`、`denoised` 和 `enhanced`；
- `QualityReport`：保存质量指标、质量标签、门控理由、生成操作和处理耗时。

每帧必须满足：

1. `raw` 永远存在；
2. `default_variant` 必须对应一个实际存在的版本；
3. M3、M4、M5 使用同一个 `default_variant`；
4. 处理失败时回退到可用的父版本，最终回退到 `raw`；
5. 颜色、亮度和去噪处理不改变像素坐标语义；
6. 去畸变会改变坐标映射，必须记录变换参数。

## 4. 处理流程

```text
CalibratedFrame
    ↓
输入检查与 RGB 规范化
    ↓
保留 raw
    ↓
计算质量指标
    ↓
标定有效且适用？──是──生成 rectified
    │
    └──否──记录跳过原因
    ↓
噪声较高且未严重模糊？──是──生成 denoised
    │
    └──否──保留当前基础版本
    ↓
低照度？──是──CLAHE-LAB，必要时叠加 Gamma
    │
    └──否──保留当前基础版本
    ↓
统一选择 default_variant
    ↓
ImageVariantSet + QualityReport
```

实际实现应将去畸变、去噪和低照度增强视为可记录的版本变换，而不是覆盖式修改图像。

## 5. 输入规范化

第一阶段的统一约定如下：

```text
色彩空间：RGB
存储类型：uint8
坐标空间：pixel
原始分辨率：保留输入分辨率
```

BDD100K 的原始帧通常为 1280×720。模型内部如果需要缩放或填充，由模型适配层处理，并记录到模型内部的坐标映射中；M2 不静默改变对外坐标语义。

## 6. 质量评价

### 6.1 第一阶段指标

指标在亮度通道上计算，建议使用灰度图或 LAB 的 L 通道：

| 指标 | 含义 | 用途 |
|---|---|---|
| `brightness_mean` | 平均亮度 | 判断整体低照度 |
| `brightness_p10` | 亮度第 10 百分位 | 观察暗部情况 |
| `underexposed_fraction` | 欠曝像素占比 | 判断暗部是否严重 |
| `overexposed_fraction` | 过曝像素占比 | 标记信息已经丢失的区域 |
| `contrast_std` | 亮度标准差 | 观察整体对比度 |
| `blur_laplacian_variance` | 拉普拉斯方差 | 判断失焦或运动模糊 |
| `noise_sigma` | 噪声估计 | 触发轻度去噪 |
| `color_cast_score` | 色偏参考分数 | 后续决定是否加入白平衡 |

过曝区域无法通过普通增强恢复细节，因此过曝指标主要用于记录和评测，不直接触发强力增强。

### 6.2 初始门控阈值

以下阈值用于第一轮跑通流程，之后根据 BDD100K 样本分布和下游指标校准：

```yaml
quality_gate:
  low_light:
    brightness_mean_lt: 60
    underexposed_fraction_gt: 0.25

  severe_low_light:
    brightness_mean_lt: 35
    underexposed_fraction_gt: 0.45

  overexposed:
    overexposed_fraction_gt: 0.03

  blur:
    laplacian_variance_lt: 80

  noisy:
    noise_sigma_gt: 8
```

单一指标不应决定所有处理。低照度至少由平均亮度和欠曝比例共同判断；模糊帧不应因为亮度低而继续叠加过强增强。

## 7. 低照度增强

### 7.1 处理步骤

1. 将 RGB 转换到 LAB；
2. 只对 L 通道使用 CLAHE；
3. 在普通低照度下使用轻度 Gamma；
4. 在严重低照度下使用更强但仍受限的 Gamma；
5. 将结果转换回 RGB；
6. 保存操作参数和父版本。

推荐初始参数：

```yaml
lowlight:
  method: clahe_lab
  clahe:
    clip_limit: 2.0
    tile_grid_size: [8, 8]
  gamma:
    enabled: true
    normal: 0.90
    severe: 0.80
```

Gamma 小于 1 用于提亮暗部。参数只从质量门控结果决定，不能逐帧大幅变化，否则视频中容易出现亮度闪烁。

### 7.2 版本命名

建议使用以下版本：

| 版本 | 生成条件 | 父版本 |
|---|---|---|
| `raw` | 始终生成 | 无 |
| `rectified` | 标定有效且适用 | `raw` |
| `denoised` | 噪声高且未严重模糊 | 当前基础版本 |
| `enhanced` | 低照度门控触发 | 当前基础版本 |

如果一帧同时需要去噪和低照度增强，操作顺序固定为：

```text
基础版本 → 轻度去噪 → CLAHE-LAB → Gamma
```

`enhanced` 的操作记录应包含全部步骤。

## 8. 版本选择规则

| 质量状态 | `default_variant` 建议 | 记录内容 |
|---|---|---|
| 正常 | `raw` 或有效的 `rectified` | 正常质量 |
| 噪声较高 | `denoised` | 去噪参数 |
| 低照度 | `enhanced` | 低照度指标和增强参数 |
| 低照度且噪声高 | `enhanced` | 去噪和增强的完整链路 |
| 严重过曝 | 当前基础版本 | 过曝标签，不强行修复 |
| 严重模糊 | 当前基础版本 | 模糊标签，不执行去模糊 |
| 任意处理失败 | 最近可用版本，最终为 `raw` | 失败原因和回退记录 |

第一阶段使用 BDD100K 时，如果没有验证过的相机标定，默认链路为：

```text
raw → 质量评价 → 条件去噪/低照度增强 → default_variant
```

## 10. 代码实现边界

建议把 M2 拆成以下可替换组件：

```text
m2/
├── input_validator.py       # 输入检查和 RGB 规范化
├── quality_metrics.py       # 质量指标计算
├── rectification.py         # 有效标定下的去畸变
├── denoise.py               # 条件性轻度去噪
├── lowlight.py              # CLAHE-LAB 和 Gamma
├── variant_builder.py       # 版本生成和操作记录
├── gate.py                  # default_variant 选择
└── schemas.py               # I3 数据结构
```

主入口保持单一决策点：

```python
image_variants, quality_report = m2.process(calibrated_frame)
```

内部处理顺序固定为：

```text
validate
→ normalize
→ quality_metrics
→ optional_rectification
→ optional_denoise
→ optional_lowlight_enhancement
→ variant_selection
→ report
```

## 11. 训练阶段的数据增强

训练增强与在线 M2 处理分开配置。第一阶段可使用 Albumentations 加入：

- 亮度和对比度变化；
- Gamma 变化；
- 高斯噪声；
- 运动模糊和失焦模糊；
- JPEG 压缩损坏；
- 随机阴影；
- 轻度色偏。

训练增强不写入 `ImageVariantSet`，不改变实际推理链路。裁剪、缩放、透视等几何增强必须同步变换 bbox、polygon、mask 和坐标映射。

## 12. 验收与对照实验

### 12.1 M2 自身验收

- 每帧都有 `raw` 和 `QualityReport`；
- 每帧都有可用的 `default_variant`；
- M3、M4、M5 消费相同版本；
- 增强和去噪不改变像素坐标语义；
- 标定缺失时不生成 `rectified`；
- 处理失败可以回退到 `raw`；
- 相同输入、配置和实现版本能得到可复现结果；
- 记录门控原因和处理耗时。

### 12.2 下游指标

增强是否启用，使用下游结果判断：

| 模块 | 指标 |
|---|---|
| M3 | 匹配数量、RANSAC 内点率、变换估计失败率 |
| M4 检测 | mAP、召回率、夜间切片指标 |
| M4 跟踪 | IDF1、ID Switch、轨迹断裂率 |
| M5 | mIoU、边界质量 |
| 系统 | 单帧处理时间、显存和 CPU 占用 |

至少比较 `raw`、`CLAHE-LAB + Gamma` 和条件去噪三种策略，并按正常、低照度、模糊、过曝、遮挡等切片统计结果。

## 13. 第一阶段实施顺序

1. 实现输入检查、RGB 规范化和 `raw` 版本；
2. 实现质量指标和 `QualityReport`；
3. 实现门控逻辑，先支持 `raw` 与 `enhanced`；
4. 实现 CLAHE-LAB 和受限 Gamma；
5. 加入条件去噪和失败回退；
6. 接入 M3、M4、M5，强制统一 `default_variant`；
7. 在 BDD100K 代表性切片上校准阈值；
8. 根据下游指标决定是否保留每类处理。
