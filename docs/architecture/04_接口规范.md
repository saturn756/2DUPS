# 04 接口规范

接口由连接推导：`03_数据流与连接逻辑.md` 定义了模块之间有哪些边、每类边缺失时怎么办；本文件把这些边固化为**字段与不变量**。**先有连接，再有接口**——因此本文件的每一条规定，都能追溯到连接逻辑中的某条边或某条不变量。配套图：`../figures/图1-2_数据流与连接图.svg`（图 1-2，边上标注接口名）。

## 4.1 接口与连接的映射

| # | 接口 | 承载的边 | 生产 → 消费 | 类型 | 生命周期 |
|---|---|---|---|---|---|
| I1 | DatasetManifest | E03 | M1 → 全链路、评测与验证 | 必需（运行级前提） | 运行级（初始化一次，只读） |
| I2 | CalibratedFrame | E02、E11（仅标定状态） | M1 → M2（必需）；M1 → M6（可选） | 必需 + 可选 | 逐帧 |
| I3 | ImageVariantSet / QualityReport | E04、E05、E06 / E16 | M2 → M3、M4、M5 / M2 → 评测与验证 | 必需 / 控制 | 逐帧 |
| I4 | MatchResult | E12、E13 | M3 → M4 跟踪子块、M6 | 可选 | 图像对级 |
| I5 | DetectionSet | E07 | M4 检测子块 → M4 跟踪子块（对外可读） | 必需（模块内部） | 逐帧 |
| I6 | TrackSet | E08 | M4 跟踪子块 → M6 | 必需 | 逐帧（增量 + 活跃状态） |
| I7 | SegmentationMap | E09 | M5 → M6 | 必需 | 逐帧 |
| I8 | SceneGraph2D | E10 | M6 → 对外输出 | 必需（唯一对外契约） | 逐帧 / 帧窗口 |
| I9 | EvaluationRecord | E17 | 评测与验证 → 归档 / 报告 | 运行级产物 | 运行级 |

## 4.2 通用约定

| 约定 | 内容 |
|---|---|
| 命名 | 接口名固定；字段名 `snake_case` |
| 强制随行字段 | 每个接口都必须能回答四件事：**哪一帧**（`frame_id`）、**哪个图像版本**（`variant_id`，涉及图像输入时）、**哪个实现与配置**（`producer_ref` / `config_ref`）、**哪个标定状态**（`calibration` 或 `geometry_status`） |
| 失败表达 | 一律用状态字段（`status` / `state` / `geometry_status` / `missing_inputs`）表达，禁止用缺省值或空值掩盖 |
| 引用而非内嵌 | 图像、掩码、点集等大对象一律用引用（`*_ref`）传递，接口本身只承载结构化描述 |
| 可选字段 | 允许新增字段；消费方必须容忍未知字段；语义变更须升大版本 |
| 禁止内容 | 禁止传递高维特征张量、模型内部中间量、模块私有状态 |
| 类别语义 | 任何类别编号必须引用类别模式（`class_schema_ref`），禁止下游按编号猜语义 |
| 时间方向 | 任何结果只能用于其自身的帧及之后的帧；禁止使用未来帧（对应 R8） |

## 4.3 逐接口规范

### I1 DatasetManifest（边 E03）

| 字段 | 说明 |
|---|---|
| `manifest_id` / `version` | 清单标识与版本（数据集 + 切分 + 采集批次） |
| `source` / `license` | 来源与许可，决定可用范围 |
| `splits` | 训练 / 验证 / 测试的样本范围 |
| `samples[]` | `sample_id`、时间戳、`media_ref`、可选 `annotation_ref`、`slice_tags[]`（低照度 / 遮挡 / 远距离等） |
| `checksum` | 内容校验 |

- **生成条件**：任一模块处理样本之前（运行级前提）。
- **缺失时**：不允许开始运行，属于硬前提而非降级项。
- **不变量**：样本可追溯到来源与许可；切片标签必须显式；禁止任何模块凭文件名推断来源或版本。

### I2 CalibratedFrame（边 E02 必需、E11 可选）

| 字段 | 说明 |
|---|---|
| `frame_id` / `timestamp` / `camera_id` | 帧与相机标识 |
| `media_ref` | 图像引用（不内嵌像素） |
| `coordinate_space` | 坐标系标识（像素 / 校正后 / 参考平面） |
| `calibration` | `{status: valid\|missing\|stale, params_ref}` |
| `manifest_ref` | 指回 DatasetManifest |

- **生成条件**：每一帧输入被 M1 接受后。
- **缺失 / 不适用时**：`status ≠ valid` 时下游**禁止**输出具有物理尺度含义的结论，只能给图像平面关系（E11 的降级行为）。
- **不变量**：`coordinate_space` 必填；状态三态齐全；标定状态变化必须逐帧反映，不允许沿用过期状态。

### I3 ImageVariantSet / QualityReport（边 E04/E05/E06、E16）

| 字段 | 说明 |
|---|---|
| `frame_id` | 帧标识（对齐键） |
| `variants[]` | 每项含 `variant_id`、`kind`（raw / enhanced / …）、`media_ref`、`params_ref` |
| `default_variant` | 默认推荐版本；三条支路必须使用同一版本（对应 R2） |
| （QualityReport）`metrics[]` | 质量指标名值对 |
| （QualityReport）`gate_decision` + `reason[]` | 门控决策与理由 |

- **生成条件**：`CalibratedFrame(t)` 到达且处理完成。
- **缺失 / 不适用时**：若处理失败，仍须产出 `raw` 版本并把门控决策置为 `use_raw`，不得阻塞下游。
- **不变量**：`raw` 版本必须始终存在；门控决策必须带理由；处理参数必须随版本记录以保证可复现；同一帧分发给 M3/M4/M5 的 `variant_id` 必须一致。

### I4 MatchResult（边 E12、E13，均为可选）

| 字段 | 说明 |
|---|---|
| `pair` | `{frame_a, frame_b, variant_id}`：参与估计的两帧与所用图像版本 |
| `keypoints_ref` / `matches_ref` / `inlier_mask_ref` | 对应关系与内点标记（引用） |
| `transform` | `{type, params, inlier_ratio, residual}` |
| `status` | `ok / unreliable / failed` |
| `producer_ref` | 实现与配置标识 |

- **生成条件**：相邻两帧同版本图像齐备（滞后一帧）。
- **缺失 / 不适用时**：缺边时跟踪不做补偿（E12）、M6 不用几何证据（E13），两处都必须在各自输出中标记。
- **不变量**：`status ≠ ok` 时 `transform` 不得被当作有效几何证据；结果只能用于 `frame_b` 及其之后的帧；`pair.variant_id` 必须与所用图像版本一致。

### I5 DetectionSet（边 E07，模块内部必需，对外可读）

| 字段 | 说明 |
|---|---|
| `frame_id` / `variant_id` / `coordinate_space` | 帧、输入版本、坐标系 |
| `objects[]` | `object_id`、`class_ref`、`bbox`、`score` |
| `producer_ref` | 实现与配置标识 |

- **生成条件**：`ImageVariantSet(t)` 到达且检测完成。
- **缺失 / 不适用时**：检测为空时也必须产出空集合 + 状态（区分"确实没有目标"与"检测失败"）。
- **不变量**：`class_ref` 必须能在类别模式中解析；坐标系与输入版本不得缺省；该接口同时供评测与验证单独评测检测，**检测指标必须与跟踪指标分开统计**。

### I6 TrackSet（边 E08 必需）

| 字段 | 说明 |
|---|---|
| `frame_id` | 当前帧 |
| `tracks[]` | `track_id`、`class_ref`、`frames[]`、逐帧状态、`state`、`confidence` |
| `state` | `tracked / lost / new / unreliable` |
| `association_ref` | 关联依据：是否使用了相机运动补偿、关联配置标识 |

- **生成条件**：`DetectionSet(t)` 到达且关联完成。
- **缺失 / 不适用时**：无检测输入的帧不更新轨迹，但须在输出中标记 `detection_missing`。
- **不变量**：轨迹状态必须显式；`unreliable` 轨迹不得单独作为冲突 / 相邻关系的判据；是否启用几何补偿必须可从 `association_ref` 读出。

### I7 SegmentationMap（边 E09 必需）

| 字段 | 说明 |
|---|---|
| `frame_id` / `variant_id` | 帧与输入版本 |
| `class_map_ref` | 区域结果引用 |
| `class_schema_ref` | 类别模式引用 |
| `producer_ref` | 实现与配置标识 |

- **生成条件**：`ImageVariantSet(t)` 到达且分割完成。
- **缺失 / 不适用时**：该帧标记 `segmentation_missing`，M6 按 E09 的降级规则处理。
- **不变量**：类别语义必须经类别模式映射；输出分辨率与坐标空间必须显式记录；细长结构若需单独口径，须在接口中附带说明字段。

### I8 SceneGraph2D（边 E10 必需，唯一对外契约）

| 字段 | 说明 |
|---|---|
| `frame_id` / `window` | 当前帧与所用帧窗口定义 |
| `nodes[]` | `{node_id, type: object\|region\|track, ref}` |
| `edges[]` | `{src, dst, relation, evidence[], confidence}` |
| `geometry_status` | `full / degraded / image_plane` |
| `missing_inputs[]` | 本帧缺失的输入（如 `[segmentation]`） |
| `provenance` | 各来源接口与实现标识 |

- **生成条件**：本帧轨迹与区域齐备，或等待达到上限后按降级规则输出。
- **缺失 / 不适用时**：缺轨迹或缺分割时仍输出，但必须列出 `missing_inputs` 并相应收窄关系类型。
- **不变量**：只输出证据充分的关系；`geometry_status` 必须真实反映几何可用性；每条边必须可追溯到证据类型与来源；不得用缺省关系填充不确定项。

### I9 EvaluationRecord（边 E17，运行级产物）

| 字段 | 说明 |
|---|---|
| `run_id` / `module_ref` / `sub_block` | 运行标识、模块与子块（检测 / 跟踪必须可分） |
| `slice` | 数据切片标识 |
| `metrics[]` | 指标名值对 |
| `failures[]` | `{sample_ref, failure_tag, cause_module}` |
| `implementation_ref` / `config_ref` | 实现与配置版本 |

- **生成条件**：离线评测运行结束。
- **不变量**：任一总体指标可追溯到模块、切片与失败样本；实现与配置版本必须随记录保存；检测与跟踪的子块指标必须分开统计。

## 4.4 对齐与聚合规则

由 `03_数据流与连接逻辑.md` 的 C1–C8 推导出的字段级规则：

| 规则 | 内容 | 落地字段 |
|---|---|---|
| R1 | 任何跨模块数据都能回答"来自哪一帧" | `frame_id` 必填 |
| R2 | 同一帧的三条并行支路必须同版本 | `variant_id` 一致；`default_variant` 由 M2 决定 |
| R3 | 任何结果可回答"由哪个实现与配置产生" | `producer_ref` / `config_ref` |
| R4 | 任何几何结论可回答"基于哪个标定状态" | `calibration.status` / `geometry_status` |
| R5 | 任何失败可被下游识别，不必猜测 | `status` / `state` / `missing_inputs` |
| R6 | 可选边缺失不改变必需边语义 | 可选字段必须有明确缺省语义（如"未使用几何证据"） |
| R7 | 任何关系结论可追溯到证据 | `edges[].evidence` + `provenance` |
| R8 | 不使用未来帧 | `pair(frame_a, frame_b)` 与消费时机约束 |
| R9 | 帧窗口定义一致 | `SceneGraph2D.window` 必须与评测与验证切片口径一致 |

## 4.5 降级语义（跨接口统一）

| 情形 | 应当输出 | 禁止 |
|---|---|---|
| 标定缺失 / 过期 | 图像平面关系 + `geometry_status = image_plane` | 输出带物理单位或地面距离的结论 |
| 几何匹配不可靠 | `MatchResult.status = unreliable`；跟踪标记未补偿；M6 `geometry_status = degraded` | 用低质量变换参与关系判定 |
| 图像质量差 | `gate_decision = use_raw` 并给出理由 | 静默使用处理后版本 |
| 检测缺失 | 空 `DetectionSet` + `detection_missing` 标记 | 用上一帧检测顶替 |
| 轨迹不可靠 | `TrackSet.state = unreliable` | 用该轨迹作冲突关系判据 |
| 分割缺失或超时 | 输出仍生成，`missing_inputs = [segmentation]` | 用其它帧掩码补齐 |
| 证据不足 | 关系标记为"不确定"并保留证据列表 | 用缺省关系填充 |

## 4.6 版本策略与变更流程

**版本策略**

| 变更 | 版本 | 要求 |
|---|---|---|
| 新增可选字段 | 小版本 | 消费方忽略未知字段即可，不阻塞 |
| 字段语义变化 / 删除字段 | 大版本 | 必须同步通知所有消费方，并更新本文件映射表 |
| 新增 / 删除连接（边） | 大版本 | 必须先改 `03_数据流与连接逻辑.md`，再改本文件 |

**变更流程**

1. 提出变更（字段、语义或连接）；
2. 判断类型：**连接变更** → 先改 03；**模块职责变更** → 先改 01 / 02；
3. 更新本文件与 `../figures/图1-2_数据流与连接图.svg`；
4. 同步下游材料（图 1-1、调研报告、架构决策文档、PPT 等）；
5. 在决策记录中留痕：改了什么、为什么、影响哪些模块与哪些边。
