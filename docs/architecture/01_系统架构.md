# 01 系统架构

## 1.1 目标与范围

**目标**：在公开道路单目 RGB 图像 / 视频上，离线复现一条可评测、可替换、可追溯的二维感知链路，并把检测、跟踪、分割和帧间几何结果融合为**二维场景结构描述**。

本项目的准确定位是：

> 单目 RGB 道路视频的 2D 感知与 2D 场景结构融合原型。

### 范围内

- 视频或图像序列的帧级接入与元数据管理；
- 可选相机标定状态的传递与验证；
- 输入格式规范化、质量评价、可选去畸变和增强；
- 图像平面上的帧间几何估计；
- 全图逐帧目标检测与跨帧目标跟踪；
- 全图逐帧语义分割；
- 目标、区域和图像平面关系的结构化融合；
- 离线评测、失败记录和降级分析。

### 范围外

- 激光雷达、毫米波雷达、热成像等多模态融合；
- 三维检测、单目深度、BEV 表征和三维重建；
- 真实距离、真实速度、物理碰撞时间和车辆动力学建模；
- 规划、行为决策、控制和实车部署认证。

### 边界假设

- 输入至少包含一条有序的单目 RGB 图像序列；
- 相机标定可以有效、缺失或过期，不能假设始终存在；
- 没有有效深度或地面模型时，所有关系默认解释为图像平面关系；
- 不同数据集的检测、分割和标定数据可以分别评测，但不能未经对齐就宣称构成同一联合真值。

## 1.2 架构风格

采用**模块化离线流水线**。模块之间只通过结构化接口通信；图像、掩码、匹配点等大对象使用引用传递；实现可以替换，但不得改变接口语义。

系统由六个运行时模块组成，评测与验证作为贯穿层，不作为第七个运行时模块：

- **M1 输入接入与标定状态管理**：读取序列、帧和可选标定信息，形成统一帧元数据；
- **M2 输入规范化与图像质量评价**：检查输入，生成可选图像版本，并选择统一下游版本；
- **M3 帧间几何估计**：估计相邻帧的图像平面对应和整体变换，为跟踪补偿提供可选证据；
- **M4 多目标检测与跟踪**：全图逐帧检测，并把检测结果关联成带 ID 的时序轨迹；
- **M5 语义分割**：逐帧输出与输入帧对齐的像素级类别图；
- **M6 2D 场景结构融合**：把目标轨迹、语义区域和可选几何证据组织成 2D 场景图。

## 1.3 六个模块职责总览

| 模块 | 一句话职责 | 输入 | 输出 |
|---|---|---|---|
| M1 输入接入与标定状态管理 | 建立序列、帧、坐标空间和标定状态 | 视频/图像序列、可选标定引用、数据清单 | `CalibratedFrame`、`DatasetManifest` |
| M2 输入规范化与图像质量评价 | 检查输入、生成可选版本并选择统一下游版本 | `CalibratedFrame` | `ImageVariantSet`、`QualityReport` |
| M3 帧间几何估计 | 从相邻图像估计图像平面变换和匹配可信度 | 两个同版本 `ImageVariantSet` | `MatchResult` |
| M4 多目标检测与跟踪 | 全图逐帧检测并进行跨帧身份关联 | 连续 `ImageVariantSet`、可选 `MatchResult` | `DetectionSet`、`TrackSet` |
| M5 语义分割 | 全图逐帧输出源帧对齐的像素类别图 | `ImageVariantSet` | `SegmentationMap` |
| M6 2D 场景结构融合 | 融合目标、区域和图像平面关系 | `TrackSet`、`SegmentationMap`、可选 `MatchResult` 与标定状态 | `SceneGraph2D` |

### M4 的两个子块

| 子块 | 职责 | 输出 |
|---|---|---|
| 检测子块 | 默认对整幅图像逐帧检测，输出类别、bbox 和置信度 | `DetectionSet` |
| 跟踪子块 | 预测历史轨迹、关联当前检测、管理轨迹状态 | `TrackSet` |

检测和跟踪合并为 M4，但指标必须分开统计。检测回答“当前帧有什么目标”，跟踪回答“当前目标是否仍是之前的那个目标”。

## 1.4 主数据流

```text
视频 / 图像序列 + 可选标定引用 + DatasetManifest
                       │
                       ▼
          M1 输入接入与标定状态管理
                       │ CalibratedFrame
                       ▼
          M2 输入规范化与图像质量评价
                       │ ImageVariantSet（统一 default_variant）
          ┌────────────┼────────────┐
          ▼            ▼            ▼
        M3           M4           M5
   帧间几何估计   检测与跟踪    语义分割
          │            │            │
          │            └─ TrackSet  │
          │                         └─ SegmentationMap
          └──── 可选几何证据 ───────┐
                                     ▼
                         M6 2D 场景结构融合
                                     │
                                     ▼
                              SceneGraph2D
```

约束：

1. M2 始终保留 `raw`，去畸变和增强均为条件性操作；
2. M3、M4、M5 使用同一帧的同一个 `default_variant`；
3. M3 只能为 M4 跟踪和 M6 提供可选证据，不能阻塞检测、分割主链路；
4. M6 输出的是 2D 场景结构，不把图像平面关系自动解释成三维或物理关系；
5. 任一输入缺失都必须显式记录并按规则降级，不能用其他帧或其他版本静默顶替。

## 1.5 M6 的能力边界

没有深度、地面模型或可靠标定时，M6 基础版只输出：

- 目标属于某个语义区域；
- 目标在另一目标左侧或右侧；
- 目标框重叠；
- 目标出现在某个区域；
- 轨迹和区域结果是否在当前帧成功对齐。

基础版不输出或不承诺：

- 目标真实前后关系；
- 真实空间邻近关系；
- 目标与自车的真实距离或速度；
- 碰撞冲突、TTC 或驾驶风险。

这些能力可以作为未来的深度、地面平面或风险评估扩展，不属于当前 `SceneGraph2D` 的基础语义。

## 1.6 评测与验证

评测与验证读取各模块输出，不产生运行时必需数据：

- M1：帧完整性、坐标和标定状态一致性；
- M2：质量指标、版本选择、处理耗时和下游影响；
- M3：匹配内点率、残差、可用率和退化行为；
- M4：检测精度、召回、IDF1、ID Switch、轨迹连续性；
- M5：mIoU、边界质量、细长结构表现和源帧对齐；
- M6：关系准确率、图结构合法率、输入对齐成功率和降级正确性。

所有结果必须能追溯到序列、帧、切片、实现、配置和失败样本。

## 1.7 骨架冻结项与实现自由项

| 骨架冻结 | 实现自由 |
|---|---|
| 六个模块及职责边界 | 模块内部算法和模型版本 |
| 主数据流和可选 M3 依赖 | 阈值、输入分辨率和性能优化 |
| 接口名称、字段语义和对齐规则 | 数据集具体切分和训练策略 |
| 失败显式、缺失降级、只传结构化结果 | M4 关联细节、M5 时序优化等内部实现 |
| M6 只输出当前定义的 2D 关系 | 将来增加深度、地面模型或风险扩展 |
