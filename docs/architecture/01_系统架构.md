# 01 系统架构

## 1.1 目标与范围

**目标**：在公开道路 RGB 图像 / 视频上，离线复现一条完整的单模态 2D 感知流程——从图像输入与标定，到多目标检测与跟踪、语义分割与场景理解，并保证每个环节可独立评测、可替换实现、失败可追溯。

**范围内**：单目 RGB 输入；2D 图像平面上的感知与定位；六个模块的职责、接口与数据流；离线评测与安全分析。

**范围外**：激光雷达 / 毫米波雷达 / 热成像等多模态输入；三维检测与 BEV 表征；高精地图与建图；规划、行为仲裁与运动控制；实车部署与实时性认证。

**边界假设**：不假设输入自带可靠标定；不假设存在额外传感器；不假设公开数据能提供全部任务的标注。

## 1.2 架构风格与依据

采用**模块化流水线**：把系统拆成边界清晰、接口明确的若干环节，每个环节可独立实现、独立训练/标定、独立评测，错误可定位。领域经典架构（感知与定位 → 规划 → 行为仲裁 → 运动控制，另设安全监控）即此形态；本项目只覆盖其中的感知与定位，并把课程收尾阶段的集成测试对应为**评测与验证**（安全监控）。

在感知内部按**并列支路**组织，共六个模块：

- **目标支路（what）**：**多目标检测与跟踪**（M4）—— 回答"有什么目标、它们如何随时间移动"。检测与跟踪合成一个模块：两者共享同一输入与同一评价对象（目标），检测结果是跟踪的唯一前置，拆开会产生"半成品模块"。
- **几何与结构支路（where/how）**：**几何特征提取与自运动估计**（M3）＋ **语义分割**（M5）—— 回答"自车如何运动、道路与背景结构在哪里"。语义分割独立成模块：它与检测任务正交（像素级分类 vs 实例级定位），指标口径不同，实现可独立替换。
- **汇合点**：**场景理解与拓扑推理**（M6）—— 融合轨迹、区域与几何证据，输出结构化场景描述。它是两条通路的终点，也是唯一的对外结构化输出。
- **基础环节**：**采集与相机标定**（M1）、**图像预处理与质量评价**（M2）—— 为上述模块提供统一坐标系与可用图像。

## 1.3 六个模块职责总览

| 模块 | 一句话职责 | 输入（接口） | 输出（接口） | 通路 |
|---|---|---|---|---|
| M1 采集与相机标定 | 建立统一图像坐标系与标定状态 | 图像序列、相机参数、数据清单 | CalibratedFrame、DatasetManifest | 基础 |
| M2 图像预处理与质量评价 | 产出可用图像版本并给出质量结论 | CalibratedFrame | ImageVariantSet、QualityReport | 基础 |
| M3 几何特征提取与自运动估计 | 由图像对估计帧间几何变换与可信度 | ImageVariantSet（图像对） | MatchResult | 几何 |
| M4 多目标检测与跟踪 | 单帧实例级目标感知 + 跨帧身份关联与轨迹管理 | ImageVariantSet（连续帧）、可选 MatchResult | DetectionSet（内部）、TrackSet | 目标 |
| M5 语义分割 | 输出像素级区域结构 | ImageVariantSet | SegmentationMap | 结构 |
| M6 场景理解与拓扑推理 | 融合轨迹、区域与几何证据，输出结构化场景 | TrackSet、SegmentationMap、可选 MatchResult 与标定状态 | SceneGraph2D | 汇合 |
| 评测与验证 | 切片评测、失败标签、降级决策回注 | 各模块输出与指标 | EvaluationRecord | 贯穿 |

### M4 的两个子块

M4 内部含检测与跟踪两个子块，**模块边界对外不变**：

| 子块 | 职责 | 输出 |
|---|---|---|
| 检测子块 | 单帧实例级目标（类别 + 位置 + 置信度） | DetectionSet |
| 跟踪子块 | 跨帧身份关联、轨迹状态管理 | TrackSet |

DetectionSet 虽然成为模块内部接口，但**仍作为对外可读的接口保留**：评测与验证需要用它单独评测检测精度（与跟踪指标分开），否则"检测差"和"关联差"无法区分。

## 1.4 数据流与并行结构

```
输入源
  └─ M1 采集与标定 ── CalibratedFrame ──> M2 预处理与质量评价
                                            │
              ┌─────────────────────────────┼─────────────────────────────┐
              │                             │                             │
     M3 几何特征与自运动估计        M4 多目标检测与跟踪            M5 语义分割
          （几何）                  （目标）                     （结构）
              │                    ├ 检测子块 → DetectionSet
              │                    └ 跟踪子块 → TrackSet
              │                             │                             │
              └── 几何证据（可选）──────────┴──────────────┬──────────────┘
                                                          ▼
                                             M6 场景理解与拓扑推理
                                                          │
                                                SceneGraph2D（对外契约）

评测与验证：环绕 M1–M6，按数据切片评测 → EvaluationRecord；门控与降级决策回注 M2
```

- 三条并行支路（M3、M4、M5）的输入都来自 M2 的图像版本，彼此不构成前置依赖；
- M3 的输出有两个可选消费者：M4 的跟踪子块（相机运动补偿）与 M6（几何证据）；
- M6 是唯一的汇合点，也是唯一的对外结构化输出。

## 1.5 评测与验证

评测与验证不产出被下游消费的数据，它的对象是其它模块：

- 按**数据切片**（正常 / 低照度 / 模糊 / 遮挡 / 远距离 / 相机运动 / 标定缺失）汇总指标；
- 记录**失败标签**并归因到模块与子块（检测 / 跟踪要能分开归因）；
- 把**门控与降级结论**回注 M2 等模块；
- 输出 EvaluationRecord，做到"任一总体指标可追溯到模块、切片与失败样本"。

## 1.6 骨架冻结项与实现自由项

| 类别 | 内容 |
|---|---|
| **骨架冻结**（改动需同步全部材料） | 六个模块的划分与职责；M4 内含检测与跟踪两个子块这一结构；并列支路与汇合点；9 个接口的名称、字段与不变量；"语义与几何分离""失败必须显式""可选输入缺失时降级"三条约束 |
| **实现自由**（实施阶段确定） | 各模块采用的具体算法 / 模型与版本；参数与阈值；数据集与切分；评测基线数值；性能优化手段；M4 内部两个子块的实现方式与是否共享骨干 |

> 判断标准：如果某个改动会影响**模块职责、模块边界或接口**，它属于骨架变更，必须先改本文档并走同步流程；如果只是替换某个模块内部的做法且接口不变，属于实现变更，记录在决策记录里即可。
