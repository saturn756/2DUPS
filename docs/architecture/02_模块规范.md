# 02 模块规范

本文件是当前系统架构的唯一维护版本。项目定位为单目 RGB 道路视频的 2D 感知课程原型，不输出真实距离、深度、TTC、碰撞风险、规划或控制结论。

## 2.1 主链路

课程阶段与代码模块对应如下：

```text
数据源
  ↓
M0 数据接入与标准化
  ↓ I2
M1 图像预处理与质量评价
  ↓ I3
M2 目标检测 ───────────────┐
  ↓ I5                      │
M3 语义/车道分割 ───────────┤
  ↓ I7                      │
M4 多目标跟踪 ← I5 + 可选 I4│
  ↓ I6                      │
M5 系统集成与场景理解 ←──────┘
  ↓ I8
输出视频 / 可视化 / 场景关系

E 评测层：贯穿 M0–M5，输出 I9
```

M0–M5 是运行时模块，E 是贯穿所有任务的评测层。I1 是运行级数据清单；I2–I8 是帧级或帧对级结果；I9 是评测记录。

当前状态：M0 支持 BDD100K 视频及 KITTI Road 独立图片；KITTI 接入已通过合成数据测试，尚未验证真实数据。M1、M2 YOLO11n 检测和 M4 的 ByteTrack/BoT-SORT 跟踪可运行；M3、M5 和 E 仍是骨架。可选帧间几何尚未实现，不属于主模块编号。

## 2.2 五层数据工程

M0 按以下五层解耦：

| 层 | 职责 | 当前实现 |
|---|---|---|
| 数据源层 | BDD100K、KITTI、Cityscapes、CULane、MOT 或自采视频 | BDD100K 五段样本 |
| 适配器层 | 解析各数据集媒体、标注、标定和元数据 | `data/adapters/bdd100k.py` |
| 标准化层 | 转换为 `DatasetManifest`、`CalibratedFrame`、统一标注引用 | `contracts/`、`data/manifest.py` |
| 存储层 | 原始数据、中间数据、模型输出和引用的本地组织 | `data/`、`outputs/`、`checkpoints/` |
| 服务层 | 校验、抽取、导出和可视化命令 | `scripts/`，逐步补齐 |

新增数据集应只增加适配器和清单，不修改 M1–M5 的算法代码。所有图像结果必须保留 `sequence_id`、`frame_id`、`variant_id`、`coordinate_space` 和来源引用。

## 2.3 M0：数据接入与标准化

M0 从数据源获得有序帧、标注、相机信息和成像参数，生成 I1 与 I2。它负责格式差异，不负责检测、分割或跟踪。

| 项目 | 内容 |
|---|---|
| 输入 | 视频/图像序列、数据集标注、可选标定文件、来源许可 |
| 输出 | `DatasetManifest`（I1）、`CalibratedFrame`（I2）和同进程 RGB 像素载体 |
| 必需元数据 | 序列、帧号、时间戳、尺寸、相机 ID、坐标空间、标定状态 |
| 可选成像参数 | FPS、曝光、ISO、增益、白平衡、畸变模型、GPS、天气、安装位置 |

BDD100K 没有经过本项目验证的统一内参时，I2 必须为 `calibration.status=missing`。KITTI Road 的原生 `training/calib/<stem>.txt` 在生成 I1 清单时解析 `P2`，转换为 `twodups.camera_params/1`，并由 M0 按图像尺寸输出 `valid` 或 `stale`；这表示已知相机内参，不表示已经生成去畸变图像。自采数据必须尽量记录时间、GPS、天气、曝光和 ISO；缺失字段不能伪造。

M0 按 `source` 显式选择现有读取器，不使用动态注册表。KITTI Road 每张图片输出一帧，`frame_index=0`、时间戳为空；其道路掩码仅作为评测引用，图片不得串成视频跟踪。M1 消费统一帧，不依赖数据集名称。通用视频和有序图片序列入口尚未实现。

棋盘格采集与参数求解属于独立标定工具，不是每帧运行的硬前置。M0 不把标注中的目标 ID 直接当作系统 Track ID，也不根据单目图像生成深度或真实距离。

## 2.4 M1：图像预处理与质量评价

M1 负责解码后的 RGB 检查、尺寸/颜色规范化、质量评价、可选去噪和低照度增强，输出 I3 `ImageVariantSet` 与 `QualityReport`。

- `raw` 永远保留；增强版本必须带父版本、参数和引用。
- 一次评测运行固定一种默认版本，例如全程 `raw` 或全程 `enhanced`，不得按帧静默切换。
- 若实验必须逐帧切换，必须记录切换点，并在切换处禁止跨版本几何匹配或重置/降级跟踪。
- 没有有效标定时不得生成 `rectified`。

M1 的增强效果必须通过 M2/M3/M4 的下游指标比较，不能仅凭亮度或视觉观感宣称有效。

## 2.5 M2：目标检测

M2 读取同一 I3 `default_variant` 的 RGB 像素，输出当前帧 I5 `DetectionSet`。当前 YOLO11 适配器支持 n/m；默认 n 权重和类别配置不变，官方 COCO m 使用 `configs/m2_detection_yolo11m.yaml` 固定路径与 SHA-256，专用 BDD100K n 独立保留。

- 全图逐帧检测；暂不预设固定边缘 ROI。
- 类别至少覆盖车辆、行人、非机动车、交通标志和交通灯等项目选定类别。
- 检测失败必须输出 `status=failed`，不能用空集合伪装成功。
- COCO 类别与各数据集类别必须通过显式映射后再评测。

M2 只负责检测，不维护跨帧身份。检测指标为 mAP、AP50、Precision、Recall、误检率和关键目标漏检率。

## 2.6 M3：语义/车道分割

M3 读取 I3，输出 I7 `SegmentationMap`。第一版覆盖可行驶区域、道路语义和车道线中的项目选定类别；不负责实例 ID。

模型内部可以缩放、裁剪或归一化，但输出必须带源尺寸、输出尺寸和必要的映射引用，确保能回到源帧坐标。分割指标为 mIoU、Dice、Pixel Accuracy；车道线另报 Lane F1 或 IoU。

## 2.7 M4：多目标跟踪

M4 根据连续 I5 检测结果维护跨帧 Track ID，输出 I6 `TrackSet`。默认不依赖标定或 M3 几何；可选 I4 只用于图像平面运动补偿。

当前复用 Ultralytics 8.3.184；原 `configs/m4_tracking.yaml` 保留 ByteTrack 逐类关联基线（新建阈值 0.25、无补偿）。跟踪脚本默认 `configs/m4_tracking_stable.yaml`，使用 BoT-SORT 高/低分关联和 Kalman 预测，不启用 ReID；保留 0.10 以上检测，新建阈值 0.25、丢失缓冲 45 个输入帧。car/truck/bus 限定在同一类别命名空间内共同关联，其他类保持隔离。最近 5 次观测分数加权投票且至少 3 票才更换输出细类；类别模式不变。标准检测入口配置不变。

稳定版在 M4 内消费与 I5 对齐的 RGB 运行时载体：屏蔽移动目标框，前后向稀疏光流和 RANSAC 估计背景相似变换，再将变换用于 BoT-SORT 预测均值/协方差。每帧只估计一次，各关联组共用。点数、内点率、覆盖范围、残差、缩放、旋转或平移检查失败时退回单位变换，原因写入 `motion.jsonl`；不跨版本使用，也不扭曲图像。该内部像素补偿不依赖外部 I4；可选几何模块仍未实现。单一变换存在视差局限。

1. 序列切换时清空状态；
2. 新检测生成 `new`；稳定配置最近 5 个输出帧中至少 3 次高分匹配后为 `tracked`（确认前保持 `new`，低分匹配不计数）；
3. 当前检测缺失时只能为 `lost` 或 `unreliable`，不得复用上一帧 bbox 作为当前检测；
4. 超过最大丢失帧数后删除轨迹；
5. 不同 `variant_id` 的相邻帧不进行几何补偿。

M4 的运行时调用另传 I2 的 `frame_index`，要求同序列逐帧连续递增；该参数不是 I5/I6 新字段。首次运行和序列切换可从任意帧开始；跳帧、倒序、重复帧须拒绝。`track_buffer` 以输入帧数计，检测失败帧也推进生命周期。切换图像版本或坐标、尺寸、类别模式后重新关联。

视频显示层单独做因果框平滑；大位移、明显尺度变化或漏检后不沿用旧平滑状态，I5/I6 不被显示层改写。灰色框为候选，彩色框为已确认 ID。

第一轮工程对照见 `docs/experiments/09_检测跟踪工程调参.md`；白天 raw 仅为实验输入策略，不改变 M1 逻辑。

跟踪指标为 MOTA、IDF1、ID Switch、轨迹连续性和丢失恢复率，当前尚未做正式评测；同输入视频的轨迹数和短轨迹数只是诊断，不能替代真值指标。

## 2.8 M5：系统集成与场景理解

M5 汇总 I5、I6、I7 和可选 I4，生成 I8 `SceneGraph2D`，并负责输出带框、掩码、Track ID 的可视化视频与集成报告。

第一版可以输出图像平面关系，例如 `inside_region`、`belongs_to`、`left_of`、`right_of` 和 `overlaps`。每条关系必须附带证据、来源和置信度。

M5 不输出真实前后关系、真实距离、真实速度、TTC、碰撞风险或控制指令。标定缺失时仍可输出图像平面关系，但必须标记能力边界。

## 2.9 可选帧间几何

帧间特征匹配、单应矩阵和相机运动补偿保存在 `optional_geometry`，输出 I4。它不是课程主链路的硬前置：M3/M4/M5 即使没有 I4 也必须能降级运行。

相邻帧默认版本不同，不能生成或沿用 I4 变换；调用方应记录 `variant_switch`。

## 2.10 E：统一评测层

E 不改变模块输出，只读取预测、真值、数据切片和运行配置，生成 I9 `EvaluationRecord`。评测必须按序列划分 train/validation/test，不能随机拆散同一视频的帧。

| 任务 | 指标 |
|---|---|
| 检测 | mAP、AP50、Precision、Recall、误检率、关键目标漏检率 |
| 分割 | mIoU、Dice、Pixel Accuracy、Lane F1 |
| 跟踪 | MOTA、IDF1、ID Switch、轨迹连续性 |
| 系统 | FPS、单帧延迟、显存、失败率 |

“安全”在本项目中只表示关键目标漏检率、失败状态和降级行为的可审计性，不代表真实自动驾驶安全认证。

## 2.11 当前数据能力边界

仓库中的 BDD100K 五段数据只用于 M0/M1 接入和 M2 检测烟雾测试；每段只有一个参考标注帧，不能用于正式跟踪、分割或泛化评测。后续应分别接入 KITTI Tracking、CULane、Cityscapes 或 MOT，并通过 M0 适配器进入相同标准化接口。
