# 02 模块规范

本文件把系统架构中的六个模块固化为可实现、可替换、可评测的模块边界。它规定每个模块“负责什么、输出什么、不能声称什么”，不规定具体模型必须如何实现。

## 2.1 通用约定

| 约定 | 规则 |
|---|---|
| 坐标语义 | 除非接口明确声明，否则 bbox、掩码和点坐标均属于当前图像的 `coordinate_space`，不能默认具有真实尺度。 |
| 对齐键 | 图像相关结果至少按 `sequence_id + frame_id + variant_id + coordinate_space` 对齐；图像对结果还必须带 `frame_a`、`frame_b`。 |
| 失败表达 | 失败、缺失、过期和降级必须通过状态字段和原因显式表达，不能用上一帧或默认值静默代替。 |
| 大对象传递 | 图像、掩码、关键点和历史轨迹使用带 URI、类型和校验和的引用，不把大对象直接塞入接口。 |
| 类别语义 | 所有类别均通过 `class_schema_ref` 和 `class_ref` 解释，禁止按整数编号猜测含义。 |
| 时间方向 | 第一版为离线处理，但结果仍遵守因果方向：第 t 帧不能使用未来帧结果。 |
| 可替换性 | 替换模块内部实现不得改变接口名称、字段语义和降级语义。 |

## 2.2 模块总览

| 模块 | 标准名称 | 主要输入 | 主要输出 | 第一版范围 |
|---|---|---|---|---|
| M1 | 输入接入与标定状态管理 | 视频/图像序列、清单、可选标定引用 | `DatasetManifest`、`CalibratedFrame` | 建立帧标识和标定状态，不强制在线标定 |
| M2 | 输入规范化与图像质量评价 | `CalibratedFrame` | `ImageVariantSet`、`QualityReport` | 检查、质量评价、可选校正/增强、版本门控 |
| M3 | 帧间几何估计 | 同版本相邻帧 | `MatchResult` | 估计图像平面对应和变换，不直接输出真实自运动 |
| M4 | 多目标检测与跟踪 | `ImageVariantSet`、可选 `MatchResult` | `DetectionSet`、`TrackSet` | 全图逐帧检测，tracking-by-detection |
| M5 | 全图逐帧语义分割 | `ImageVariantSet` | `SegmentationMap` | 输出源帧坐标对齐的像素类别图 |
| M6 | 2D 场景结构融合 | `TrackSet`、`SegmentationMap`、可选几何状态 | `SceneGraph2D` | 生成可审计的图像平面关系，不做 3D 风险推理 |

## 2.3 M1：输入接入与标定状态管理

### 职责

M1 负责把视频或有序图像序列接入系统，建立 `sequence_id`、`frame_id`、时间戳、相机标识、图像尺寸和来源信息，并绑定可选的标定引用。它是“输入与标定状态管理”模块，不是必须在每次运行时执行棋盘格标定的模块。

### 处理步骤

1. 读取 `DatasetManifest` 和样本媒体引用；
2. 解码视频或枚举图像序列，生成稳定且不跨序列重复的帧标识；
3. 记录原始尺寸、时间戳、相机标识和像素坐标语义；
4. 查找与当前相机、数据集和分辨率匹配的标定引用；
5. 将标定状态标记为 `valid`、`missing` 或 `stale`，并把原因写入输出。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | 视频/图像序列、来源许可、可选内参/畸变参数或标定文件引用 |
| 输出 | `DatasetManifest`、逐帧 `CalibratedFrame` |
| 必需状态 | `sequence_id`、`frame_id`、`image_size`、`coordinate_space`、`calibration.status` |

### 边界

- 标定缺失不阻塞主链路；后续模块必须能在 `raw` 像素坐标下运行。
- 数据集声称的相机参数不能未经验证直接标记为 `valid`；至少要记录来源、适用相机和适用分辨率。
- M1 不根据单目视频臆造深度、距离、速度或地面平面。
- 棋盘格采集、参数求解和重标定可以作为独立工具或离线子流程，但不属于 M1 每帧运行的硬前置。

### 验收维度

帧解码完整率、帧标识唯一性、时间顺序正确率、来源可追溯率、标定状态与适用范围一致性。

## 2.4 M2：输入规范化与图像质量评价

### 职责

M2 对 M1 输出做输入检查和质量评价，生成可追溯的图像版本，并选择一个统一的 `default_variant` 供 M3、M4、M5 使用。

### 处理步骤

1. 检查图像是否可读、尺寸和通道是否满足约定；
2. 计算亮度、对比度、模糊、噪声、过曝/欠曝等质量指标；
3. 在标定状态有效且参数适用时，按配置生成 `rectified`；
4. 按质量门控条件生成可选 `enhanced`；
5. 在所有版本中选择 `default_variant`，记录选择理由和处理操作。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | `CalibratedFrame` |
| 输出 | `ImageVariantSet`、`QualityReport` |
| 不变式 | `raw` 永远存在；默认版本必须存在；同一帧的下游支路使用同一默认版本 |

### 边界

- 去畸变不是必做步骤；没有有效标定时不得生成伪造的 `rectified`。
- 增强不能覆盖原始输入，所有变换都必须记录参数、父版本和坐标影响。
- 模型内部缩放不改变对外坐标语义；输出结果仍须能映射回源帧。
- M2 不在这里做目标检测、跟踪或语义分割。

### 验收维度

输入检查通过率、质量指标稳定性、版本可追溯率、门控决策一致性、处理后坐标映射正确率、下游指标变化。

## 2.5 M3：帧间几何估计

### 职责

M3 从同一序列的相邻帧中估计图像平面上的对应关系和整体变换，为 M4 跟踪补偿提供可选证据，也为 M6 记录几何可用性。第一版不把单应矩阵或匹配结果直接解释为真实相机位姿、深度或速度。

### 处理步骤

1. 读取相邻帧的同一 `variant_id`；
2. 提取局部特征或其他可替换的对应表示；
3. 建立候选匹配；
4. 使用 RANSAC 等方法剔除外点并估计图像平面变换；
5. 根据内点率、残差、退化检查和匹配数量给出 `ok`、`unreliable` 或 `failed`。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | `ImageVariantSet(t-1)` 与 `ImageVariantSet(t)`，同序列、同版本 |
| 输出 | `MatchResult`，包含 `pair`、匹配引用、变换、质量指标和状态 |
| 变换语义 | 默认是 `image_plane_transform`；不得默认为 `metric_motion` |

### 边界

- `status != ok` 时，变换不能被下游当作有效几何证据。
- M3 失败不能阻塞 M4 检测、M4 普通跟踪或 M5 分割。
- M3 不负责解决尺度、深度、前后关系、真实速度或碰撞风险。
- 结果只能用于当前及之后的允许消费时刻，不得引用未来帧。

### 验收维度

匹配内点率、重投影/变换残差、可用率、退化检测召回、在相机运动和低纹理切片下的降级正确率。

## 2.6 M4：多目标检测与跟踪

M4 包含检测子块和跟踪子块，二者接口相连但指标分开统计。

### 检测子块

- 默认对整幅图像逐帧检测，不预设“只在边缘一圈检测”的固定区域；ROI 只能作为经验证的优化配置。
- 输出当前帧目标的类别、bbox、置信度和检测状态。
- 空集合必须区分“当前确实未检测到目标”和“检测失败/输入缺失”。

### 跟踪子块

1. 读取上一帧及历史轨迹状态；
2. 用简单运动模型预测轨迹位置；
3. 在 `MatchResult(t-1,t)` 有效时，可先进行图像平面运动补偿；
4. 将当前 `DetectionSet(t)` 与预测轨迹关联；
5. 管理新建、跟踪、丢失和不可靠状态，并在序列切换时清空状态。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | 连续 `ImageVariantSet`、当前 `DetectionSet`、可选 `MatchResult` |
| 输出 | `DetectionSet`、`TrackSet` |
| 跟踪状态 | `new`、`tracked`、`lost`、`unreliable` |

### 边界

- 跟踪的意义是维护跨帧身份、历史轨迹和短时预测，不是替代每帧检测。
- 检测缺失时不得把上一帧 bbox 冒充当前检测；只能按生命周期保留为 `lost` 或 `unreliable`。
- M3 只改变可选的运动补偿，不是 M4 的硬前置。
- 跟踪 ID 不能跨 `sequence_id` 复用，除非另有明确的全局 ID 设计。

### 验收维度

检测精度、召回、类别一致性、IDF1、ID Switch、轨迹连续性、丢失恢复率、检测缺失和几何失败时的降级正确率。

## 2.7 M5：全图逐帧语义分割

### 职责

M5 对每一帧整幅图像进行语义分割，输出与源帧坐标对齐的类别图或类别区域引用。M5 只负责像素类别，不负责实例 ID；目标与区域的关系由 M6 根据 M4 与 M5 的结果融合。

### 处理规则

- 类别由 `class_schema_ref` 定义，至少要能解释道路、车道线/可行驶区域等项目选定类别。
- 模型内部可缩放、裁剪或归一化，但必须提供 `source_size`、`map_size` 和 `alignment_ref`。
- 第一版默认逐帧处理，不使用未来帧做时序修补。
- 分割失败、超时或无法映射回源帧时，必须输出失败状态，不得将内部尺寸结果当作源帧结果。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | `ImageVariantSet` 的统一 `default_variant` |
| 输出 | `SegmentationMap` |
| 必需信息 | 帧/版本/坐标对齐键、类别模式、掩码引用、映射引用、状态 |

### 验收维度

mIoU、类别召回、边界质量、细长结构质量、源帧对齐正确率、分割缺失时的状态和降级准确率。

## 2.8 M6：2D 场景结构融合

### 职责

M6 把 M4 的带 ID 目标轨迹、M5 的语义区域和可选的 M3 几何状态组织为 `SceneGraph2D`。它是可审计的规则化融合层，不是没有深度信息时的三维场景理解器。

### 第一版节点与关系

节点只保留两类：

- `track`：引用 M4 的 `track_id`，表示当前帧的目标轨迹；
- `region`：引用 M5 的类别区域，如道路、可行驶区域或车道线区域。

第一版关系限定为：

- `belongs_to`：目标按明确的 bbox/掩码证据属于某语义区域；
- `inside_region`：目标框或采样点落在某区域内部；
- `left_of` / `right_of`：在当前图像坐标中的水平相对位置；
- `overlaps`：两个 bbox 或区域投影有明确重叠；
- `appears_in`：轨迹在当前帧或窗口中出现于某区域。

关系必须附带证据类型、来源接口和置信度。没有足够证据时不补边。

### 处理步骤

1. 检查 `TrackSet` 与 `SegmentationMap` 的帧、版本、坐标空间和尺寸是否对齐；
2. 创建 track 节点和 region 节点；
3. 根据 bbox、底部中心点、掩码采样和水平坐标生成候选关系；
4. 过滤不可靠轨迹和无效分割结果；
5. 写入 `geometry_status`、`missing_inputs`、证据、来源和降级原因。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | `TrackSet`、`SegmentationMap`、可选 `MatchResult` 和标定状态 |
| 输出 | `SceneGraph2D` |
| 基础几何状态 | 默认 `image_plane`；对齐或输入质量不足时可为 `degraded` |

### 明确不输出

- 真实前后关系、真实空间邻近和三维拓扑；
- 真实距离、真实速度、TTC、碰撞冲突和驾驶风险；
- 规划、决策或控制指令。

### 降级规则

- 缺少标定：仍可输出图像平面关系，`geometry_status=image_plane`；
- M3 不可靠：不使用其几何证据，记录 `match_unreliable`；
- M5 缺失或未对齐：不输出对象—区域关系，但保留有证据的目标侧关系；
- M4 轨迹不可靠：不以该轨迹单独生成关系边；
- 输入帧或版本不一致：拒绝聚合，输出对齐失败状态，不静默修正。

### 验收维度

输入对齐成功率、区域归属准确率、左右关系准确率、重叠关系准确率、关系证据完整率、图结构合法率和降级准确率。

## 2.9 评测与验证

评测与验证是贯穿层，不作为第七个运行时模块。每个阶段都要保存 `implementation_ref`、`config_ref`、`manifest_ref`、数据切片、失败原因和可复现输入引用。M4 检测与跟踪必须分开评测；M6 的关系指标必须明确是图像平面关系指标，不能以此宣称真实三维能力。
