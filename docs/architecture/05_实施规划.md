# 05 实施规划

本文件把已经冻结的 2D 感知骨架拆成可验收的实现阶段。目标是先打通“输入 → 2D 感知 → 2D 场景结构”，再做可替换的算法增强；当前不把深度、三维风险或控制纳入基础链路。

## 5.1 骨架与实现的边界

| 属于骨架（改动需同步） | 属于实现（记录决策即可） |
|---|---|
| 六个模块的划分与职责；M4 的检测/跟踪子块 | 模型、特征、关联算法和推理框架 |
| I1–I9 接口字段与状态语义 | 阈值、分辨率、批大小和缓存策略 |
| M2 后三条支路及 M3 的可选依赖 | 具体质量门控策略和优化参数 |
| 对齐键、失败显式和降级路径 | 日志格式、错误码细节和性能优化 |
| M6 的 2D 关系集合与禁止项 | 未来的深度/地面模型扩展实现 |

## 5.2 实施顺序

| 步骤 | 模块 | 要填的实现 | 验收重点 |
|---|---|---|---|
| S1 | M1 | 数据清单、视频/图像解码、帧 ID、标定引用和状态判定 | 帧顺序可复现、来源可追溯、标定缺失可正常下发 |
| S2 | M2 | 格式检查、质量指标、可选校正/增强、默认版本门控 | `raw` 永远可用；版本和坐标映射可复现 |
| S3 | M3 + M4 检测 | 匹配与图像平面变换；全图逐帧检测和类别策略 | 几何状态可评测；检测覆盖率和检测指标独立可评测 |
| S4 | M4 跟踪 | 预测、关联、生命周期、序列重置、可选几何补偿 | IDF1、ID Switch、轨迹连续性和降级行为可评测 |
| S5 | M5 + M6 | 源帧对齐分割；区域归属、左右、重叠等 2D 规则 | 分割/对齐/关系指标独立，证据和降级可审计 |
| S6 | 评测与验证 | 切片、失败标签、运行记录和报告自动化 | 每个指标可追溯到实现、配置、样本和失败原因 |

顺序原则：先打通输入和接口，再分别验证目标链路、区域链路和 2D 融合。每一步可以替换内部实现，但不应为了某个模型临时改变接口语义。

## 5.3 各阶段产物

### S1：输入和标定状态

- 一份可版本化的 `DatasetManifest`；
- 可枚举的 `CalibratedFrame`；
- 标定来源、适用相机/分辨率和 `valid/missing/stale` 判定记录；
- 棋盘格重标定工具作为独立工具时，输出可被 M1 引用的标定文件。

### S2：输入版本和质量门控

- 每帧至少包含 `raw`；
- `ImageVariantSet` 与 `QualityReport` 的 JSON 示例和解析校验；
- 默认版本选择策略及回退比例；
- 去畸变/增强的坐标映射和失败标签。

### S3–S4：检测、跟踪和帧间几何

- `MatchResult` 的图像平面语义和可用性判据；
- 全图逐帧 `DetectionSet`；
- `TrackSet` 的生命周期、关联证据和序列重置；
- M3 缺失或不可靠时 M4 仍能运行的对照结果。

### S5：分割和 2D 场景结构

- 固定版本的 `class_schema_ref`；
- 源帧对齐的 `SegmentationMap`；
- `SceneGraph2D` 的规则表、证据类型和关系级置信度；
- 对无深度限制的说明：关系是图像平面关系，不代表三维空间关系。

## 5.4 评测体系

| 层级 | 评测内容 | 主要产物 |
|---|---|---|
| M1 | 帧完整性、时间顺序、来源和标定状态一致性 | 输入质量表 |
| M2 | 质量指标、版本选择、坐标映射、处理耗时 | 质量报告 |
| M3 | 内点率、残差、可用率、退化判定 | 几何评测记录 |
| M4 检测 | precision、recall、mAP 或课程选定检测指标 | 检测评测记录 |
| M4 跟踪 | IDF1、ID Switch、轨迹连续性、丢失恢复 | 跟踪评测记录 |
| M5 | mIoU、边界质量、细长结构表现、源帧对齐率 | 分割评测记录 |
| M6 | 对齐成功率、区域归属准确率、左右/重叠准确率、图合法率、降级准确率 | `SceneGraph2D` 评测记录 |
| 链路级 | 端到端成功率、耗时、缺失输入比例和降级触发比例 | 运行报告 |

M6 的关系指标必须注明是人工规则标注或基于哪一种 2D 真值生成，不能把它们宣传为真实前后关系、碰撞风险或自动驾驶安全指标。

## 5.5 实现选型流程

每个模块内部实现均按以下流程记录：

1. 列出至少两个候选，其中至少一个为可解释的传统或轻量方案；
2. 使用相同 manifest、相同切片和相同输入版本建立对照；
3. 按本模块验收维度评测，不能只看单张可视化；
4. 比较精度、可复现性、依赖、显存/内存和运行时间；
5. 记录采纳、放弃和适用条件，并保留可切换的对照实现。

## 5.6 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据没有联合标注 | 无法直接评测端到端关系 | 按模块分开评测，显式记录样本交集和真值口径 |
| 没有可信标定 | 不能支持米制或三维解释 | 主链路继续用像素坐标，M6 固定为 `image_plane` |
| 单目缺少深度 | 无法验证真实前后/邻近/风险关系 | M6 只保留 2D 关系；深度、地面模型和风险另立扩展 |
| M3 匹配退化 | 跟踪可能身份错乱 | M3 为可选补偿；失败时回退普通跟踪并显式记录 |
| 分割和检测不对齐 | 目标—区域关系失真 | 固定四元对齐键和 `alignment_ref`，未对齐则拒绝聚合 |
| 增强损害下游 | 默认版本选择失效 | 保留 raw，按切片比较下游指标后再启用增强 |
| 关系缺少真值 | M6 指标不稳定 | 先固定可审计规则，进行人工抽检并保存规则版本 |

## 5.8 里程碑

| 检查点 | 通过判据 |
|---|---|
| 骨架评审 | 六个模块职责无重叠，接口和降级语义完整 |
| 链路打通 | 输入到 `SceneGraph2D` 可运行，缺失输入不崩溃且状态明确 |
| 可替换性验证 | 至少替换一个模块实现，下游无需改接口 |
| 评测闭环 | 指标可追溯到模块、切片、配置和失败样本 |
| 架构定稿 | 2D 基础语义冻结；新增深度/风险能力另行扩展和升版本 |
