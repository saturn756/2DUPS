# 05 实施规划

本文件回答一个问题：**骨架已经定了，接下来按什么顺序把实现填进去，每一步产出什么、怎么验收。**

## 4.1 骨架与实现的边界

| 属于骨架（改动需走同步流程） | 属于实现（记录进决策记录即可） |
|---|---|
| 六模块的划分与职责；M4 内含检测与跟踪两个子块 | 每个模块内部的算法 / 模型选择；两个子块是否共享骨干 |
| 9 个接口的字段与不变量 | 参数、阈值、输入分辨率策略 |
| 并列支路结构与数据流方向 | 模块内部的子结构（如 M6a 内是否增设子分支） |
| 「失败显式」「可选输入降级」「只传结构化结果」 | 具体错误码取值、日志格式 |
| 模块的验收维度（看什么） | 指标阈值与基线数值 |

## 4.2 填充顺序

按课程阶段推进，每一步只填一层，保持接口不变：

| 步骤 | 对应阶段 | 要填的实现 | 该步结束时应能证明 |
|---|---|---|---|
| S1 | 阶段二 | M1：标定与数据清单的具体做法、数据来源与切分 | 坐标系与标定状态可复现、可核验；样本可追溯 |
| S2 | 阶段三 | M2：质量处理手段、质量指标与门控规则 | 处理后对下游指标不劣；门控决策可解释 |
| S3 | 阶段四 | M3：特征与匹配、外点剔除、可用性判据；M4 检测子块：检测实现与规模 | 几何在标定有效时可核验；检测在分组口径下可评测 |
| S4 | 阶段四–五 | M4 跟踪子块：关联与状态管理、是否启用几何补偿 | 轨迹身份与状态可评测；相机运动下不劣化；检测与跟踪指标可分开统计 |
| S5 | 阶段五 | M5：分割实现与类别模式；M6：关系类型与判定规则 | 区域指标与关系指标可独立统计 |
| S6 | 课程收尾阶段 | 评测与验证：切片定义、失败标签、评测流程自动化 | 任一指标可追溯到模块、切片与失败样本 |

> 顺序原则：**先链路通，再逐点加强**。S1–S2 打通「输入 → 图像版本」，S3–S4 打通「目标链路」，S5 补齐「结构链路」，S6 收口评测。

## 4.3 实现选型流程

每个模块的实现在确定前，走同一条流程（结果写入决策记录，包含：候选、对照、指标、结论、影响）：

1. **列候选**：至少两个可选实现，其中一个为可解释的传统方案或轻量方案；
2. **设对照**：明确对照口径——同一数据切片、同一输入版本、同一评测脚本；
3. **定指标**：用该模块的验收维度（见 `02_模块规范.md`），不接受"只看单张效果图"；
4. **看代价**：延迟、内存、依赖、可复现性（是否公开权重 / 是否需训练）；
5. **记结论**：写明采纳哪个、放弃哪个、为什么；若结论依赖某个假设，把假设一起写下；
6. **留退路**：为每个模块保留一个可切换的对照实现，验证接口的可替换性真实成立。

## 4.4 评测体系

| 层级 | 内容 | 产出 |
|---|---|---|
| 模块级 | 每个模块的验收维度独立统计（几何精度、检测分组精度、轨迹稳定性、区域精度、关系正确性） | 模块指标表 |
| 切片级 | 正常 / 低照度 / 模糊 / 遮挡 / 远距离 / 相机运动 / 标定缺失 | 切片对比表 |
| 链路级 | 端到端从输入到 SceneGraph2D 的时延与降级触发情况 | 运行记录 |
| 失效级 | 失败标签 + 归因模块 + 样本引用 | EvaluationRecord |

评测脚本与数据切分需可复现：同一 run 必须能由 `implementation_ref + config_ref + manifest version` 重新跑出同样结果。

## 4.5 风险与降级策略

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据缺少联合标注 | 无法在统一子集上做多模块消融 | 用数据清单显式记录样本交集；必要时按模块分别评测并在报告中说明口径 |
| 标定信息不可靠 | 几何结论不可信 | 按接口不变量强制降级为图像平面关系，并记录降级比例 |
| 处理后图像反而伤害下游 | 门控决策失效 | 保留原始版本，门控以「吞吐量/质量/下游指标」三者为准 |
| 相机运动未被补偿 | 跟踪身份错乱 | M3 的几何结果作为补偿输入；不可用时在 TrackSet 中标记降级 |
| 关系推理无真值 | 关系指标缺基准 | 采用规则判据 + 人工抽检；把规则本身作为可审计对象 |

## 4.7 里程碑与检查点

| 检查点 | 判据 |
|---|---|
| 骨架评审通过 | 六个模块职责无重叠、9 个接口字段与不变量完整、降级语义覆盖主要失败情形 |
| 链路打通 | 输入 → SceneGraph2D 能跑通，且在所有降级情形下都能给出带状态的结果而不是崩溃 |
| 可替换性验证 | 至少有一个模块替换实现后，下游无需改动即可运行 |
| 评测闭环 | 任一总体指标可追溯到模块、切片与失败样本 |
| 架构定稿 | 骨架变更冻结，实现变更只走决策记录 |
