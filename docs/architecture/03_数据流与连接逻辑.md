# 03 数据流与连接逻辑

本文件定义**模块之间怎么连、按什么顺序流动、缺了会怎样**。配套图：`../figures/图1-2_数据流与连接图.svg`（图 1-2，逐边标注编号与接口）。接口规范（`04_接口规范.md`）由本文件的连接清单推导得出：**先有连接，再有接口**——接口字段必须能支撑这里定义的每一条边。

## 3.1 基本约定

| 约定 | 内容 |
|---|---|
| 连接唯一性 | 模块之间只能通过本文档定义的边通信；不允许共享内存、回调、全局状态等隐式通道 |
| 数据单元 | 帧级（单帧）、图像对级（相邻两帧）、序列级（连续多帧）、运行级（一次完整评测） |
| 三类边 | **数据边**（实线，必需）、**可选依赖边**（虚线，缺失可降级）、**控制/评测边**（虚线，不参与运行时数据流） |
| 对齐键 | 所有数据边都必须携带 `frame_id`；涉及图像版本时还必须携带 `variant_id`；图像对还需携带 `pair(frame_a, frame_b)` |
| 版本一致性 | 同一帧进入多条并行支路时，必须使用同一 `variant_id`，不允许各支路各自挑选图像版本 |
| 离线语义 | 全链路离线处理，不做实时背压与抢占；因此允许"等齐再算"，但**不允许用别的帧顶替缺失输入** |

## 3.2 各模块的处理单元与状态

| 模块 | 处理单元 | 触发条件 | 是否可滞后 | 内部状态 |
|---|---|---|---|---|
| M1 采集与相机标定 | 序列 / 帧 | 输入到达 | 否 | 数据清单、标定参数、切片标签 |
| M2 图像预处理与质量评价 | 帧 | `CalibratedFrame(t)` 到达 | 否 | 无（逐帧独立） |
| M3 几何特征提取与自运动估计 | 图像对 | 相邻两帧图像版本齐备 | 是（天然滞后一帧） | 参考帧缓存 |
| M4 检测子块 | 帧 | `ImageVariantSet(t)` 到达 | 否 | 无（逐帧独立） |
| M4 跟踪子块 | 帧（序列累积） | `DetectionSet(t)` 到达 | 否 | 轨迹集合与状态 |
| M5 语义分割 | 帧 | `ImageVariantSet(t)` 到达 | 否 | 无（逐帧独立） |
| M6 场景理解与拓扑推理 | 帧窗口 | 本帧所需的轨迹与区域齐备（或等待超时） | 是（可容忍窗口内延迟） | 关系图、上一窗口状态 |
| 评测与验证 | 运行级 | 离线触发 | — | 无（只读采样） |

> 滞后说明：M3 使用相邻帧，因此它对第 t 帧的几何结果最早在第 t 帧图像到达后才可产出；M4 跟踪子块对第 t 帧的补偿只能使用 `pair(t-1, t)` 的几何结果，**不允许使用未来帧**。

## 3.3 连接清单

### 数据边（必需）

| 编号 | 源 → 目标 | 承载接口 | 说明 |
|---|---|---|---|
| E01 | 输入源 → M1 | （外部输入） | 图像 / 视频序列、相机参数（可选）、来源与许可信息 |
| E02 | M1 → M2 | CalibratedFrame | 带坐标系与标定状态的帧；M2 只做内容处理，不改几何 |
| E03 | M1 → 全链路 | DatasetManifest | 带外初始化：在任一模块处理样本前提供版本、切分、切片标签 |
| E04 | M2 → M3 | ImageVariantSet（图像对） | 相邻两帧的同版本图像；M3 的输入前提是两帧来自同一 `variant_id` |
| E05 | M2 → M4 | ImageVariantSet（连续帧） | 检测子块逐帧输入；同一帧的 `variant_id` 与 E04、E06 一致 |
| E06 | M2 → M5 | ImageVariantSet | 分割逐帧输入；与 E05 同帧同版本 |
| E07 | M4 检测子块 → M4 跟踪子块 | DetectionSet | 模块内部边；同时对外可读，供评测与验证单独评测检测 |
| E08 | M4 跟踪子块 → M6 | TrackSet | 轨迹与状态；M6 的目标输入 |
| E09 | M5 → M6 | SegmentationMap | 区域结构；M6 的结构输入 |
| E10 | M6 → 对外输出 | SceneGraph2D | 唯一对外结构化契约 |

### 可选依赖边（缺失可降级）

| 编号 | 源 → 目标 | 承载接口 | 缺失时的行为 |
|---|---|---|---|
| E11 | M1 → M6 | CalibratedFrame 的标定状态 | M6 的 `geometry_status` 降为 `image_plane`，只输出图像平面关系 |
| E12 | M3 → M4 **跟踪子块** | MatchResult | 供跟踪做相机运动补偿；**检测子块不使用该边**。缺失时跟踪不做补偿，在 `association_ref` 中标记未补偿 |
| E13 | M3 → M6 | MatchResult 的几何结果 | M6 不使用几何证据，`geometry_status` 降为 `degraded` |

### 控制与评测边

| 编号 | 源 → 目标 | 内容 | 说明 |
|---|---|---|---|
| E14 | 评测与验证 → 各模块 | 只读采样 | 读取模块输出与指标，不修改运行时数据 |
| E15 | 评测与验证 → M2 | 门控与降级回注 | 依据评测结论调整质量门控策略；**不改变接口**，只改策略配置 |
| E16 | M2 → 评测与验证 | QualityReport | 质量结论与门控决策，用于切片统计与归因 |
| E17 | 评测与验证 → 归档 | EvaluationRecord | 评测与失败归因的最终产物 |

## 3.4 三条并行支路的对齐逻辑

```
                 ┌── E04 ──> M3 ──┐ (E12 可选，回注跟踪)
M2 ──(同帧同版本)─┼── E05 ──> M4 ──┼── E08 ──┐
                 └── E06 ──> M5 ──┴── E09 ──┴──> M6 ── E10 ──> 输出
```

1. **同源分发**：M2 对第 t 帧产出一个 `ImageVariantSet` 后，把**同一版本**分别沿 E04/E05/E06 下发；三条支路不得各自选择版本（版本由 M2 的 `default_variant` 决定，可在配置中覆盖，但必须全局一致）。
2. **帧标识贯穿**：M3/M4/M5 的输出都必须带第 t 帧的 `frame_id` 与所用 `variant_id`，使 M6 能按帧把三条支路的结果对齐。
3. **M3 的时序**：M3 消费 `pair(t-1, t)` 并产出对应几何结果；该结果只能用于第 t 帧及之后的处理（E12 供第 t 帧跟踪补偿，E13 供第 t 帧及之后的关系判定）。
4. **M6 的齐备条件**：M6 处理第 t 帧需要 `TrackSet(t)` 与 `SegmentationMap(t)`。两者齐备即处理；若其中之一在**窗口等待上限**内未到达，则按降级规则输出，并在输出中列出 `missing_inputs`。
5. **窗口语义**：M6 判断"前 / 后 / 相邻 / 冲突"这类关系需要时间上下文，因此按**帧窗口**处理而非单帧。窗口长度与等待上限是策略参数（实现阶段填写），但**窗口定义必须与评测与验证的切片口径一致**。
6. **无顶替原则**：任何一条边缺失时，只能降级或等待，**不得用其它帧或其它版本的数据补齐**。

## 3.5 失败与降级传播路径

| 触发条件（上游） | 受影响边 | 下游行为 | 必须记录的内容 |
|---|---|---|---|
| 标定缺失 / 过期 | E11 | M6 只输出图像平面关系 | `geometry_status=image_plane`，原因 `calibration_missing` |
| 图像质量差、门控回退 | E04 / E05 / E06 | 三条支路统一使用 `raw` 版本 | `QualityReport.gate_decision=use_raw` 与理由 |
| 几何匹配不可靠 | E12 | 跟踪不做运动补偿 | `association_ref` 标记未补偿、`state=unreliable` 的轨迹比例 |
| 几何匹配不可靠 | E13 | M6 不使用几何证据 | `geometry_status=degraded`，原因 `match_unreliable` |
| 检测缺失或整体低置信 | E07 / E08 | 该帧无轨迹更新；已有轨迹按生命周期规则老化 | 帧级 `detection_missing` 标签 |
| 轨迹不可靠 | E08 | 该轨迹不参与冲突 / 相邻关系判定 | `TrackSet.state=unreliable` + 排除记录 |
| 分割缺失或超时 | E09 | M6 不输出"对象—区域"关系，仅输出轨迹侧关系 | `missing_inputs=[segmentation]` |
| M6 证据不足 | E10 | 输出"不确定"关系并保留证据列表 | 关系级 `evidence` 与 `confidence` |

**传播原则**：降级只向下游单向传播，且必须在**最近的接口**上表达出来——不允许把上游的失败在中间模块"消化掉"后继续输出看似正常的结果。

## 3.6 连接级不变量

这些不变量是接口字段设计的直接依据，逐条对应 `04_接口规范.md` 中的强制字段：

| # | 不变量 | 对应接口要求 |
|---|---|---|
| C1 | 任何跨模块数据都能回答"来自哪一帧" | 强制 `frame_id` |
| C2 | 任何跨模块数据都能回答"基于哪个图像版本" | 强制 `variant_id`（涉及图像输入的模块） |
| C3 | 任何跨模块数据都能回答"由哪个实现与配置产生" | 强制 `producer_ref` / `config_ref` |
| C4 | 任何几何结论都能回答"基于哪个标定状态" | 强制 `calibration` 或 `geometry_status` |
| C5 | 任何失败都可被下游识别，不必猜测 | 强制状态字段（`status` / `state` / `missing_inputs`） |
| C6 | 可选边缺失不改变必需边语义 | 接口中可选字段必须有明确缺省语义 |
| C7 | 同一帧的三条支路结果可被无歧义地聚合 | 统一的对齐键（`frame_id` + `variant_id`） |
| C8 | 任何关系结论都能追溯到证据类型与来源 | `edges[].evidence` 与 `SceneGraph2D.provenance` |
