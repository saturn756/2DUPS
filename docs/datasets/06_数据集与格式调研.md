# 06 数据集与格式调研

本文件只做数据集选型和格式确认，**不下载数据、不创建本地数据副本**。调研日期：2026-09-23。

## 6.1 先区分三种“标定”

| 情况 | 数据集可能提供的内容 | 对本项目的含义 |
|---|---|---|
| 已提供相机参数 | 内参、畸变、立体校正参数、外参，通常在 TXT/JSON 中 | 可作为 M1 的外部标定引用，但仍需检查相机、分辨率和坐标系 |
| 提供标定图片 | 棋盘格/圆点阵列图像和板格尺寸 | 可以重新求解内参和畸变 |
| 两者都没有 | 只有道路图像/视频和任务标注 | M1 输出 `calibration.status=missing`，主链路继续使用像素坐标 |

**有相机参数不等于有棋盘格图像。**公开道路数据集通常只提供已经记录的相机参数，不提供设备采集时拍摄的棋盘格图。若要验证我们自己的棋盘格标定流程，需要另行拍摄标定板图像。

## 6.2 候选数据集总览

| 数据集 | 原始组织形式 | 标定信息 | 主要标注 | 当前判断 |
|---|---|---|---|---|
| [BDD100K](https://github.com/bdd100k/bdd100k) | 约 40 秒道路视频；任务标签按帧关联 | Scalabel 标签允许 `intrinsics`，但该字段可能不存在 | 检测、车道、可行驶区域、语义/实例/全景分割、框跟踪、分割跟踪 | **主链路候选**；M1 默认按 `missing` 设计 |
| [KITTI Raw / Tracking](https://www.cvlibs.net/datasets/kitti/) | 按序列组织的 PNG 图像帧；Raw 还有 Velodyne/OXTS | TXT calibration 文件 | 2D/3D 目标、track ID；Raw 有多传感器数据 | **标定和几何基准**；不是 MP4 |
| [Cityscapes](https://www.cityscapes-dataset.com/) | 50 城市街景的立体序列帧 | `camera` 类型文件提供相机内外部标定 | Fine/Coarse 语义、实例、CityPersons、立体图像 | **分割和相机元数据基准** |
| [nuScenes](https://www.nuscenes.org/nuscenes) | `samples/`、`sweeps/` 和 JSON 数据库；多摄像头 | `calibrated_sensor` JSON | 3D 检测、跟踪、姿态、地图等 | **后续扩展**；不作为第一套单目主数据 |

## 6.3 BDD100K：视频主链路候选

原始核心是道路驾驶视频；训练/评测时通常把视频解码为帧，再通过视频名、帧名和帧索引关联标签。项目侧建议把 `videoName` 映射为 `sequence_id`，把 `videoName + index` 映射为 `frame_id`。图像尺寸、帧率和编码由 M1 从媒体元数据确认，不写死先验。

检测/跟踪标签是 Scalabel 兼容的 JSON frame list，典型字段如下：

```json
{
  "name": "0000f77c-6257be58.jpg",
  "videoName": "0000f77c",
  "index": 0,
  "labels": [{
    "id": "0",
    "category": "car",
    "box2d": {"x1": 500.0, "y1": 300.0, "x2": 700.0, "y2": 500.0},
    "attributes": {"occluded": false, "truncated": false}
  }],
  "attributes": {"weather": "clear", "scene": "city street", "timeofday": "daytime"}
}
```

语义分割通常是单通道 PNG，像素值是类别 ID，`255` 常用于 ignore；JSON 分割支持多边形或 RLE。可行驶区域、车道类别/方向/样式是不同任务，不能混成一个类别编号。检测类别 ID 从 1 开始，应通过 `class_schema_ref` 映射。官方格式允许 `intrinsics` 缺失，因此不能默认 `calibration.status=valid`；BDD100K 不是棋盘格标定数据集。

BDD100K 适合 M2 增强、M3 视频帧匹配、M4 检测跟踪和 M5 多任务标签读取，但必须先检查不同任务标签是否覆盖同一帧。

## 6.4 KITTI：标定和几何基准

KITTI Raw 常见结构：

```text
<date>_drive_<drive>_sync/image_00/data/*.png
<date>_drive_<drive>_sync/image_01/data/*.png
<date>_drive_<drive>_sync/image_02/data/*.png
<date>_drive_<drive>_sync/image_03/data/*.png
<date>_drive_<drive>_sync/velodyne_points/data/*.bin
<date>_drive_<drive>_sync/oxts/data/*.txt
<date>/calib_cam_to_cam.txt
<date>/calib_imu_to_velo.txt
<date>/calib_velo_to_cam.txt
```

`image_02` 是左 RGB 相机；常见标定字段包括 `P_rect_02`、`R_rect_02` 和传感器间刚体变换。Tracking 常见结构是 `image_02/0000/*.png`、`image_03/0000/*.png`、`label_02/0000.txt` 和 `calib/0000.txt`。Tracking 标签每行包含 `frame`、`track_id`、`type`、遮挡/截断、2D bbox，以及后续的 3D 尺寸、位置和旋转字段。

KITTI 提供相机/传感器参数文件，不提供棋盘格图像。它适合验证 M1 外部标定读取、M2 校正、M3 帧间几何和 M4 跟踪；但数据是图像序列而不是 MP4，M1 必须把序列目录统一成 `CalibratedFrame`。

## 6.5 Cityscapes：分割和相机元数据基准

官方路径模板是 `{root}/{type}{video}/{split}/{city}/{city}_{seq:0>6}_{frame:0>6}_{type}{ext}`。第一版重点关注：

| 类型 | 典型内容 |
|---|---|
| `leftImg8bit` | 左相机 8-bit PNG 图像 |
| `rightImg8bit` | 右相机 8-bit PNG 图像 |
| `gtFine` / `gtCoarse` | 多边形 JSON 和可转换的单通道 PNG 标签 |
| `camera` | 内部和外部相机标定文件 |
| `timestamp` / `vehicle` | 时间戳、车辆里程计/GPS 等序列元数据 |

`labelIds.png` 的像素值是类别 ID，训练时要映射到项目类别模式。`camera` 是已经记录的相机参数，不是棋盘格图片。Cityscapes 适合 M5 语义分割、M6 目标—区域 2D 关系，以及校正后坐标和 bbox 对齐验证；单目实验应固定左相机。

## 6.6 nuScenes：复杂的扩展对照

nuScenes 的核心结构是 `samples/` 关键帧、`sweeps/` 中间帧、`maps/` 地图和 `v1.0-trainval/` 等 JSON 表。主要表包括 `sample.json`、`sample_data.json`、`calibrated_sensor.json`、`ego_pose.json` 和 `sample_annotation.json`。相机图像通常是 JPEG，通过 token 关联到 sample；`calibrated_sensor` 中有 `camera_intrinsic`、旋转和平移。

nuScenes 没有把棋盘格图像作为标定输入；它适合后续验证多摄像头和 JSON 元数据关联，不作为第一套单目主数据。

## 6.7 按模块的选择建议

| 工作 | 首选 | 辅助 | 选择理由 |
|---|---|---|---|
| M1 外部标定读取 | KITTI | Cityscapes | calibration 文件清晰，适合检查相机编号、矩阵和坐标系 |
| M1 棋盘格流程 | 自行拍摄标定板 | 不依赖道路数据集 | 公开道路数据集通常不提供棋盘格图像 |
| M2 增强 | BDD100K、Cityscapes | 后续再加街景图像 | 有天气、光照、模糊和城市场景差异 |
| M3 帧间几何 | KITTI Raw、BDD100K | Cityscapes sequence | 有连续帧；KITTI 还有相机元数据 |
| M4 检测跟踪 | BDD100K、KITTI Tracking | nuScenes 相机子集 | 有连续序列和目标身份评测 |
| M5 分割 | Cityscapes、BDD100K | — | 类别图/多边形格式明确 |
| M6 2D 融合 | 同一帧交集的 BDD100K 或 Cityscapes 子集 | — | 必须同时获得目标和语义区域 |

## 6.8 暂定组合和下载顺序

第一轮不下载全部数据集。暂定组合为：

```text
BDD100K       = 视频与多任务主链路候选
KITTI         = 外部标定、帧间几何、跟踪格式基准
Cityscapes    = 语义分割、相机元数据、区域融合基准
nuScenes      = 后续多摄像头 / JSON 标定扩展
```

优先在 BDD100K 和 KITTI Tracking 之间确定主链路：BDD100K 更接近普通驾驶视频，但 M1 往往是 `missing`；KITTI 标定和跟踪格式更清晰，但组织形式是图像序列。之后用 Cityscapes 补齐分割和区域融合，不把不同数据集的帧强行拼成一条序列。

## 6.9 下载前检查清单

1. 官方入口、版本、许可和注册要求；
2. split、序列数、帧数和预计磁盘占用；
3. 图像格式、尺寸、帧率/时间戳和颜色通道；
4. 原始文件如何映射为 `sequence_id` 和 `frame_id`；
5. 检测、跟踪、分割是否存在同一帧交集；
6. 标定文件的相机编号、分辨率适用范围、坐标系和单位；
7. 是否只有外部参数，是否另需自行拍摄棋盘格；
8. 增强影响：亮度/噪声只改图像，裁剪/缩放/透视必须同步改 bbox、polygon、mask 和坐标映射；
9. 无法确认的字段标记为 `unknown`，不凭文件名猜测。
