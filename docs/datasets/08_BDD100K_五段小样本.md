# BDD100K 五段小样本

第一轮只保存 5 段 BDD100K 训练视频及其对应的 5 个原始标注 JSON，用于验证 M1 解码、M2 质量评价与增强、M3 连续帧匹配，以及 M4 在参考帧上的检测输入。数据文件仅存放在远程工作区 `/home/zsf/2DUPS/data/raw/bdd100k/`，受 `.gitignore` 排除，不提交到 GitHub。

## 来源与抽取方式

- [BDD100K 官方下载页](http://bdd-data.berkeley.edu/download.html)；
- 官方视频包：`http://128.32.162.150/bdd100k/bdd100k_videos.zip`；
- 官方原始标签包：`http://128.32.162.150/bdd100k/bdd100k_labels.zip`。

视频整包约 2 TB。`scripts/download_bdd100k_subset.py` 使用服务器支持的 HTTP Range 读取 ZIP 目录和指定成员，只抽取列出的文件。脚本核对 ZIP 成员大小，解压过程由 Python `zipfile` 校验 CRC。

视频容器为 MOV，编码为 H.264，约 40 秒、约 30 fps。抽样检查显示视频流编码尺寸为 `720×1280`，带 `rotation=+90` 或 `-90` 元数据；播放器显示为横向 `1280×720`。M1 读取时必须逐视频处理旋转元数据，不能只按编码宽高解释画面坐标。

## 标签格式与能力边界

这 5 个 JSON 使用 BDD100K 早期格式：

```json
{
  "name": "359ce11c-e2f58b33",
  "attributes": {
    "weather": "clear",
    "scene": "city street",
    "timeofday": "night"
  },
  "frames": [
    {
      "timestamp": 10000,
      "objects": [
        {
          "category": "car",
          "id": 3,
          "box2d": {"x1": 435.47, "y1": 315.68, "x2": 501.60, "y2": 369.34}
        }
      ]
    }
  ]
}
```

每个 JSON 只有约第 10 秒的一个参考帧标注，`objects[]` 中的 `id` 不能直接当作跨帧跟踪 ID。这批样本可以验证检测标签解析，但不能计算跟踪 IDF1，也不含逐帧语义分割标注。项目的统一接口使用 `labels[]` 形式时，M1 或数据适配器需要显式完成旧格式到接口格式的转换。

未获得这 5 段视频的经过验证的相机内参，M1 应输出 `calibration.status=missing`。

## 复现下载

在仓库根目录运行：

```bash
python3 scripts/download_bdd100k_subset.py \
  --name bdd100k/videos/100k/train/359ce11c-e2f58b33.mov \
  --name bdd100k/videos/100k/train/9542db5e-c825c091.mov \
  --name bdd100k/videos/100k/train/881a4fa1-30d35cf2.mov \
  --name bdd100k/videos/100k/train/3311620c-6ce84fba.mov \
  --name bdd100k/videos/100k/train/793b6756-ef820bf7.mov

python3 scripts/download_bdd100k_subset.py \
  --url http://128.32.162.150/bdd100k/bdd100k_labels.zip \
  --name 100k/train/359ce11c-e2f58b33.json \
  --name 100k/train/9542db5e-c825c091.json \
  --name 100k/train/881a4fa1-30d35cf2.json \
  --name 100k/train/3311620c-6ce84fba.json \
  --name 100k/train/793b6756-ef820bf7.json
```

默认目的地为 `data/raw/bdd100k/`。脚本遇到已有同名文件时检查大小并跳过；下载中使用 `.part`，完整读取和 CRC 校验后才改为最终文件名。源站使用 HTTP；若后续官方公布校验和，应再补充独立哈希校验。
