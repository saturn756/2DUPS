# 四类数据集格式清单

本文只描述原始数据组织、标注格式和标定字段，**不下载数据**。四个候选数据集是 BDD100K、KITTI、Cityscapes 和 nuScenes。

## 1. BDD100K

### 原始媒体

- 核心是道路驾驶视频；实际使用时通常先解码成连续图像帧。
- `videoName` 用于把帧归入同一段视频；`frameIndex` 可表示视频内帧号。
- 适合转换为项目格式：`sequence_id = videoName`，`frame_id = videoName:frameIndex`。

### 官方标签格式

BDD100K 使用 Scalabel 兼容的 JSON frame list：

```json
{
  "name": "0000f77c-6257be58.jpg",
  "url": "images/0000f77c/000000.jpg",
  "videoName": "0000f77c",
  "frameIndex": 0,
  "timestamp": 0,
  "size": {"width": 1280, "height": 720},
  "intrinsics": {
    "focal": [1000.0, 1000.0],
    "center": [640.0, 360.0]
  },
  "labels": [
    {
      "id": "0",
      "category": "car",
      "box2d": {"x1": 500.0, "y1": 300.0, "x2": 700.0, "y2": 500.0},
      "attributes": {"occluded": false, "truncated": false}
    }
  ],
  "attributes": {
    "weather": "clear",
    "scene": "city street",
    "timeofday": "daytime"
  }
}
```

### 分割和标定

- 语义分割通常是单通道 PNG，像素值表示类别 ID，`255` 常表示 ignore。
- JSON 分割可以使用 `poly2d` 或 RLE；`poly2d` 是 Scalabel 的曲线格式，不要直接当作普通 COCO polygon。
- 检测、车道、可行驶区域、语义/实例/全景分割和框跟踪使用不同任务标签。
- `intrinsics` 允许缺失，不能默认标记为有效标定；BDD100K 不提供棋盘格标定图像。

## 2. KITTI Raw / Tracking

### KITTI Raw 目录

```text
<date>_drive_<drive>_sync/
├── image_00/data/*.png
├── image_01/data/*.png
├── image_02/data/*.png       # 左 RGB
├── image_03/data/*.png       # 右 RGB
├── velodyne_points/data/*.bin
└── oxts/data/*.txt

<date>/
├── calib_cam_to_cam.txt
├── calib_imu_to_velo.txt
└── calib_velo_to_cam.txt
```

标定文本中常见 `P_rect_02`、`R_rect_02` 和传感器间刚体变换。第一版单目 RGB 可固定 `image_02`，并把相机编号写入 `camera_id`。

### KITTI Tracking 目录和标签

```text
training/
├── image_02/0000/000000.png
├── image_03/0000/000000.png
├── label_02/0000.txt
└── calib/0000.txt
```

每行标签的字段顺序可概括为：

```text
frame track_id type truncated occluded alpha
x1 y1 x2 y2
height width length x y z rotation_y
```

第一行和 bbox 用于 2D 检测/跟踪；后续尺寸、位置和旋转是 3D 标注。KITTI 提供相机参数文件，但不提供棋盘格图片；原始数据是图像序列，不是 MP4。

## 3. Cityscapes

### 路径模板

```text
{root}/{type}{video}/{split}/{city}/
    {city}_{seq:0>6}_{frame:0>6}_{type}{ext}
```

### 常见类型

| 类型 | 格式和内容 |
|---|---|
| `leftImg8bit` | 左相机 8-bit PNG 图像 |
| `rightImg8bit` | 右相机 8-bit PNG 图像 |
| `gtFine` / `gtCoarse` | 多边形 JSON 和标签 PNG |
| `camera` | 相机内部/外部标定文件 |
| `timestamp` | 序列时间戳文本 |
| `vehicle` | 车辆里程计、GPS 等元数据 |

典型文件名形式为：`city_000000_000019_leftImg8bit.png`、`city_000000_000019_gtFine_polygons.json`、`city_000000_000019_gtFine_labelIds.png`。

### 标注和标定

- `gtFine`/`gtCoarse` JSON 保存多边形；`labelIds.png` 是单通道类别图。
- `camera` 是已记录的相机参数，不是棋盘格拍摄图像。
- 主任务以图像帧标注为主，不等于连续视频的每一帧都有精细标签。
- 单目实验建议固定 `leftImg8bit`，不要把左右相机帧混成一个序列。

## 4. nuScenes

### 目录和 JSON 表

```text
<dataroot>/
├── samples/                 # 关键帧传感器数据
├── sweeps/                  # 中间帧传感器数据
├── maps/
└── v1.0-trainval/
    ├── sample.json
    ├── sample_data.json
    ├── calibrated_sensor.json
    ├── ego_pose.json
    └── sample_annotation.json
```

### 关联方式

- 相机图像通常是 JPEG。
- `sample` 表示一个时间点；`sample_data` 指向具体传感器文件。
- 各表通过 token 关联，而不是依赖文件名推断关系。
- `calibrated_sensor` 中包含 `camera_intrinsic`、旋转和平移；`ego_pose` 表示车辆姿态。
- nuScenes 是多摄像头、多传感器数据集，不提供棋盘格标定图像，不作为第一套单目主数据。

## 5. 对本项目的统一转换

无论原始格式是什么，进入项目前都转换为：

```text
DatasetManifest
  └── sample
      ├── sequence_id
      ├── frame_id
      ├── camera_id
      ├── media_ref
      ├── annotation_ref
      └── calibration_ref / calibration.status
```

| 原始数据 | 项目接口 |
|---|---|
| 视频或 PNG/JPEG 帧 | `CalibratedFrame.media_ref` |
| 数据集视频名/序列目录 | `sequence_id` |
| 文件名、帧号或 sample token | `frame_id` |
| TXT/JSON 相机参数 | `calibration_ref` |
| BDD/KITTI bbox | `DetectionSet.objects[].bbox` |
| track ID | 作为评测来源，M4 重新生成 `TrackSet.track_id` |
| 标签 PNG / polygon JSON | `SegmentationMap.class_map_ref` 或转换后的类别图 |

## 6. 当前选型结论

- 需要视频和多任务标签：优先看 BDD100K。
- 需要外部标定和连续跟踪：优先看 KITTI。
- 需要语义分割和相机元数据：优先看 Cityscapes。
- 需要复杂 JSON 标定和多摄像头扩展：再看 nuScenes。
- 四者都不能替代独立的棋盘格标定图片采集。
